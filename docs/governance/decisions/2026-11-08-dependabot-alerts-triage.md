# Decision — the six open Dependabot alerts of 2026-11-08: what is reachable, what we change, what we tolerate

Article 12 (independent security review), Article 54 (supplier compromise) · triaged 2026-11-08 by the lead, read-only, then one lockfile change · the alerts arrived with the Dependabot configuration of PR #210.

**Method.** `gh api repos/gschiemann/EDUCMS/dependabot/alerts?state=open` for the alerts and `gh api /advisories/<GHSA>` for each advisory's affected range; the dependents of every vulnerable copy were read from `pnpm-lock.yaml` (importers and snapshots sections) rather than guessed; whether a chain reaches production was decided from the dependency section (`dependencies` vs `devDependencies`) of the package that imports it and from where the API code imports it (`grep -rl modelcontextprotocol apps/*/src` → nothing).

**The change (one pull request):** `pnpm-lock.yaml` only — `qs` 6.16.0 → 6.16.1 everywhere, `@hono/node-server` 2.1.0 → 2.1.6, `@modelcontextprotocol/sdk` 1.32.1 → 1.32.2 (its range gained `zod ^4`; the dev chain keeps zod 3 until shadcn moves). No `package.json` range changes, no code.

**Blast radius.** A lockfile change rebuilds and redeploys the API and the renderer on Railway (health-gated: the old container answers until the new one passes `/api/v1/health/started`) and rebuilds the web app on Vercel. The only runtime difference is one patch of `qs` inside Express 5's query parsing. Merge off-hours, like any deploy in launch week.

**What stays open on the Dependabot page, on purpose:** #36 (zod 3 behind dev tools), #51, #53, #49. They may be dismissed as *tolerable risk* with a link to this file; the owner decides. A dismissed alert does not hide a future, different advisory on the same package.

**Validation.** CI on the pull request (the nine required checks, including the API Jest suite and the Docker boot smoke test); after the merge, `/api/v1/health` `commit` equals the merge SHA. **Rollback:** revert the pull request; the previous lockfile redeploys.
