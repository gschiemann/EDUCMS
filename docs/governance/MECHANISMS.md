# Mechanisms — VenueOS

The map from every article of the Foundry Standard to the thing that enforces it here, or an honest GAP. Built read-only on 2026-10-31 (branch `governance/foundry-standard-phase0` @ `e19294c8`) with grep, `git log` and read-only GitHub API reads; every path cited existed that day. The full record — ranked GAP backlog with its smallest next steps, the "could not verify" list and the search behind every absence claim — is the confidential decision record in the private standard repository (`decisions/2026-10-31-phase0-multi-model-review/05-mechanisms-map.md`); this public copy carries the status and the mechanisms, which are visible in the code anyway.

**Headline (54 articles): MECHANIZED 3 · PARTIAL 40 · PROSE 8 · GAP 3.** The GAP and PROSE counts may only go down; each Phase 1 item below names its article.

Status: **MECHANIZED** — a tool enforces it *on the path that matters* (a required check or a git hook for CI; on-by-default in production for a runtime mechanism) · **PARTIAL** — some tooling, some prose, including gates that run but do not block · **PROSE** — a written rule only · **GAP** — nothing. Phases: **0\*** done in this adoption (docs only) · **1** after launch · **2** when a trigger justifies it.

Two facts shape everything below: only four build checks are required to merge (the risk-weighted gates — emergency path, tenant isolation, API tests, schema-has-migration — run but do not block), and 16 of the 22 workflows skip `docs/**` and `*.md`, so a governance-only change such as this one runs no CI at all. Both are Phase 1 items (#16, #18, #45).
