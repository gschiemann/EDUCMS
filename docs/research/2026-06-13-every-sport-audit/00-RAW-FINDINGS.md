### Findings
- **[P1] soccer / config** — Soccer half auto-advances at regulation — stoppage/added time is impossible with the clock running
  - where: `apps/api/src/sports/sports.service.ts:2211`
  - problem: autoAdvanceExpiredClocks() treats a count-up clock as expired the instant `live >= segMs` (segMs = 40:00 from SOCCER.clock.segmentMs at packages/api-types/src/sports.ts:317). For soccer this rolls the half to HALFTIME / 2nd half exactly at 40:00. Real soccer plays referee-added stoppage time AFTER the regulation mark (the clock counts up past 40:00 / 45:00). So an operator literally cannot run added time while the clock is running — the half ends on its own. This also defeats the `addedTime` stat (sports.ts:323), which can never actually be played out on the clock. Workaround is to stop the clock just before 40:00 and run added time manually, which no operator will know to do.
  - fix: In sports.service.ts autoAdvanceExpiredClocks, for count-up sports do NOT auto-advance the segment at segMs — either (a) never auto-advance count-up (let the clock keep counting up past regulation and require the operator to advance the half), or (b) add the game's `addedTime` minutes to the expiry threshold (segMs + addedTime*60000) so the half only auto-rolls after added time. Pair with surfacing added time on the clock (see the board finding).
