## Per-lens grades

### Typography & type-scale — grade B-
- [P0] Display headlines at 120-200px render with default 0em letter-spacing, which looks loose and accidental — the hallmark of amateur signage. The renderer already proves the engine 'knows' big type needs negative tracking (hardcoded -0.02em on its own number widgets) but never passes it through for AI-generated headlines. → **fix:** In packages/signage-design/themes.ts add a per-theme `displayTracking` (e.g. -0.03em for sans display like Oswald/Sora/Space Grotesk, -0.015em for Poppins/Montserrat, 0 for serif Playfair/Cormorant). In art-director.ts mapTextConfig, for role display/headline emit config.letterSpacing from the theme's displayTracking; for the kicker keep 0.18em. SignageText already forwards config.letterSpacing. `packages/signage-design/themes.ts + apps/api/src/ai/art-director.ts:mapTextConfig`
- [P1] Every display is fontWeight 800 and every body 500 regardless of typeface. Playfair Display and Cormorant Garamond (worship, luxury) are serif faces whose elegance is at 700/900 with high stroke contrast — flattening them to a uniform 800 makes them look like a bold web heading, not a designed serif. Oswald is a condensed face that reads best at 500-600. → **fix:** Add `displayWeight` and `bodyWeight` to the FontPair (or ThemeBundle) in themes.ts, set per face (Playfair 800/900, Cormorant 600/700, Oswald 600, Sora/Space Grotesk 700). In archetypes.ts textTokens() and art-director.ts mapTextConfig, read theme.fontPair.displayWeight instead of the hardcoded 800. The Google Fonts href already loads the needed weights (Playfair @900, Cormorant @700). `packages/signage-design/types.ts FontPair + themes.ts + archetypes.ts:textTokens`
- [P1] 9 of 12 themes use Inter as the body and 3 (clean-corporate, calm-clinic, sky-civic) are Inter/Inter single-family. The display picks are the most predictable Google fonts. This is the difference between 'looks like a SaaS dashboard' and 'looks like a studio made it' — the single biggest 'is this world-class' lever and currently the weakest. → **fix:** Re-pair at least the flagship themes with characterful display faces (all loadable from Google Fonts): minimal-luxury → Fraunces or Cormorant display + a refined sans body; bold-retail → Archivo Expanded / Anton display; midnight-tech → Clash Display (or Space Grotesk kept) + Geist/IBM Plex; warm-school → Fredoka/Baloo display. Give every theme a body that ISN'T Inter where the mood calls for it (e.g. Source Serif for worship body). Add the new families to SIGNAGE_FONTS_HREF in WidgetRenderer.tsx. `packages/signage-design/themes.ts (the 12 bundle() calls) + apps/web/src/components/widgets/WidgetRenderer.tsx SIGNAGE_FONTS_HREF`
- [P2] lineHeight is a flat 1.1 for ALL display/headline roles (art-director.ts mapTextConfig: `lineHeight: isDisplay ? 1.1 : 1.35`). 1.1 is right for a wrapping 2-line sans headline but too tight for serif display (Playfair/Cormorant clip ascenders/descenders at 1.1) and too loose for a single-line all-caps hero. Leading is not tuned to role or typeface. → **fix:** Derive leading per role+face: serif display 1.15-1.2, sans display 1.05-1.1, single-line hero (no wrap expected) ~1.0. Add a `leading` map keyed by typeRole in type-scale.ts (it already owns the scale) and have mapTextConfig read it instead of the literal 1.1/1.35. `packages/signage-design/type-scale.ts + apps/api/src/ai/art-director.ts:mapTextConfig`
- [P2] The modular type-scale RATIO is the default Perfect Fourth (1.333) for 9 of 12 themes — only luxury/worship (1.5) and sports (1.414) differ. So a punchy retail promo, a calm clinic board, and a sleek tech launch all have the IDENTICAL headline:body proportion. Hierarchy 'feel' is a major mood lever a typographer uses and it's nearly constant here. → **fix:** Set typeScaleRatio per theme mood in themes.ts: retail/QSR/sports want a dramatic ratio (1.5-1.618 golden) so the offer dominates; clinic/civic/corporate want a calmer 1.25 (major third); luxury already 1.5. The validator's headline 2-3x band still holds because dominant roles sit at steps 2-3. `packages/signage-design/themes.ts (typeScaleRatio per bundle)`
- [P2] No tabular-figures, no true-italic emphasis, no drop-cap, no small-caps in the AI output vocabulary. stat-spotlight renders a huge number with proportional figures (a '111' looks lopsided); quote-spotlight has no drop-cap; the art-director can never request an italic emphasis word. These are the refinements that separate 'designed' from 'typeset by a template.' → **fix:** (a) For stat-spotlight's stat slot, emit fontVariantNumeric:'tabular-nums' + letterSpacing -0.02em in art-director.ts (SignageText already supports tabular via style). (b) Add an optional drop-cap treatment for quote-spotlight headline. (c) Let the refine/chat-to-edit path emit a per-span italic for emphasis. ### Color, theme systems & contrast — palette sophistication, accent discipline, neutrals/gradients, brand-derivation (HCT), surface/glow/scrim depth — grade C+
- [P0] Brand-derivation PASTEL-IZES the brand. I exercised deriveThemeFromBrand on real brands: Coca-Cola red #e61a27 -> accent #ff8980 (salmon pink), hot pink #ff1493 -> #ff83b3 (pale), navy #1b2a4a -> #9cabd2 (dusty periwinkle). Root cause: themes.ts:412 hardcodes `accent = accentPalette.tone(mode==='dark' ? 70 : 45)`. Tone 70 on a high-chroma hue lands in the light, desaturated-on-screen band, so the iconic brand color renders washed out. A brand studio would NEVER let Coca-Cola's accent be salmon. This is the single biggest 'looks AI-generated, not designer-made' tell for any branded board. → **fix:** In deriveThemeFromBrand (themes.ts:412), don't use a fixed tone. Pick the accent tone by VIBRANCY against the surface: scan tones 45->75 (dark mode) and choose the LOWEST tone whose onAccent text still clears 4.5:1 AND whose HCT chroma is preserved (prefer ~tone 50-58 for high-chroma seeds so the brand stays saturated). Keep the existing contrast loop as the safety net, but bias toward saturation, not lightness. Add a brandFidelity check: contrastRatio plus a chroma-retention assertion in themes.spec.ts. `packages/signage-design/src/themes.ts:deriveThemeFromBrand`
- [P0] Every theme is monochromatic — ONE accent hue, zero secondary/tertiary color. ThemePalette has exactly {background, surface, ink, inkInverse, accent, onAccent, muted}. There is no secondaryAccent, no success/warn semantic, no chart/category ramp. Real premium signage (and Canva/Beautiful.ai templates) use a 2-3 color accent SYSTEM — a primary + an analogous or complementary secondary for the kicker vs CTA vs stat. The art-director rule even enforces 'exactly ONE element carries accent', which is a legibility-era crutch that caps every board at one-color-pop. Result: boards read flat-palette, not rich. → **fix:** Add `accent2` (+ `onAccent2`) to ThemePalette and derive it in HCT as an analogous (+/-30deg hue) or complementary tone of the seed, contrast-verified the same way. Give each curated theme a hand-tuned accent2. Let the art-director assign accent2 to the kicker/divider while accent stays on the CTA/stat. Wire it through resolveTextHex + dividerCss.
