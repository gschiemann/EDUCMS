## Widget catalog the player/builder renders + the EXACT config fields that make each FUNCTIONAL — authoritative list for the AI board-builder. ### Injection points

- `apps/api/src/ai/art-director.ts` — `mapTextZone (~line 354) + defaultConfigFor (~line 642) + widgetType allow-map (~line 626)`: THE injection point for the AI board-builder's startup knowledge. The art-director engine maps each ResolvedZone → a widget defaultConfig here. It already knows the FUNCTIONAL field vocab the renderer reads: TEXT→{content,sizeMode:'absolute',fontSize(px),fontFamily,fontWeight,color,bgColor,alignment,lineHeight, +cardLayout/rowLayout/paddingMode:'button'/valueText/detail/accentDivider/scrimCss}; IMAGE→{fit,bgGradient,scrimCss,assetUrl}; QR renders as an IMAGE zone with {qrText} (line 626 comment: 'QR renders as an IMAGE zone'; line 660-661 emits qrText). To extend the AI's per-widget functional knowledge, add the data-binding fields cataloged above (e.g. TICKER customSync/customColumn, COUNTDOWN targetDate/periods, MENU_BOARD posSync/items, TOUCH_POINT touchAction) to the archetype slot → defaultConfig mappers here.
- `packages/signage-design/src/types.ts` — `ArtDirectorSpec / SceneSpec / ArchetypeId / ArchetypeCopy / ArchetypeImagePlan`: The art-director CONTRACT — the ONLY thing the LLM emits (archetype enum, theme id, copy slots {kicker,headline,body,cta,items[{label,value,detail}]}, image plan). LLM never emits x/y/hex/fontSize; geometry+style derived by archetypes.ts/type-scale.ts/themes.ts. To teach the AI a new functional widget it must go through an ArchetypeSlotSpec.widgetType + the art-director mapper, NOT a new raw-config path.
- `apps/web/src/components/widgets/WidgetRenderer.tsx` — `WidgetPreview switch (line 434) + cfg.variant short-circuit (line 399) + canonical-type fallback (679)`: The runtime source of truth for which widgetType→component and which config fields each reads. Any new widget the AI emits must have a case here (or a registered cfg.variant) or it renders null. The default: case (720) returns null — an unknown widgetType is silently invisible.
- `apps/web/src/components/widgets/variants-register.ts` — `registerVariant({widgetType,id,render,defaultConfig,previewOnly})`: 142KB registry of styled variant tiles keyed by widgetType (36 TEXT, 35 TICKER, 32 CLOCK/ANNOUNCEMENT, 28 WEATHER/LOGO/COUNTDOWN, 27 STAFF_SPOTLIGHT, 26 IMAGE_CAROUSEL/CALENDAR, 17 SCOREBOARD, plus 1 each for every vertical widget). cfg.variant selects one; its defaultConfig is the seed config the builder/AI starts from. This is where canonical v2 types (CORPORATE/WORSHIP/etc.) get their real renderers.
- `apps/api/src/ai/guided-intake.ts + ai.service.ts` — `guided intake → ArtDirectorSpec generation`: Where the LLM call is shaped and validated against the signage-design contract before art-director.ts resolves it to zones. The per-vertical affinity + archetype menu the LLM sees is assembled here — extend this to broaden which functional widgets/bindings the AI considers per vertical (e.g. wire posSync menu boards for QSR, GameState sports widgets for SPORTS).

### Gaps (where boards come out non-functional today)

- COUNTDOWN ships with NO targetDate → CountdownWidget renders a meaningless 'Date.now()+30 days' counter (WidgetRenderer.tsx L1131). The agent must learn to gather the event date/time and emit config.targetDate (ISO) — for purpose 'event' especially, where guided-intake explicitly pairs title-cta with a countdown.
- WEATHER ships with NO location → defaults to the placeholder city 'Springfield' (WidgetRenderer.tsx L995). - MENU is never POS-bound. required-widget 'menu' → LUNCH_MENU with no menu lines → hardcoded DEFAULT_MENU_LINES ('Monday: Pizza...'). - CTA buttons carry NO touchAction — the mapper emits zero touchAction (interactive kiosks get dead CTAs). The sanitizer already supports open-url/webhook/goto-scene/play-video (SSRF-guarded); the generator just never produces one. Agent must learn to gather a CTA destination (URL / target scene) and emit zone.touchAction.
- QR ships qrText:'https://example.com' (placeholder). Renders a real but useless QR. Agent must capture the real destination URL (often the same as the CTA target) and emit it.
- LOGO ships with no assetUrl → blank slot. Tenant brand logo URL is never threaded into the engine (only brand colors are). Agent/pipeline must inject the tenant's logo asset URL when 'logo' is requested.
- TICKER ships a literal placeholder 'Add your scrolling message here' — the model is never asked to write ticker copy, so a requested ticker is a fill-in-the-blank, not real content.
- Real background PHOTOS are the exception, not the rule: image-bg archetypes default to a themed gradient + scrim (mapImageConfig has no assetUrl); a photo only appears with an explicit withImage/intake.background='photo' opt-in AND a working image provider AND not on the 3-candidate fan-out. split-50's image half is ALWAYS a placeholder gradient (image-gen never targets it). So most 'photo' boards visibly lack imagery.
- Net pattern: the pipeline is excellent at TEXT + layout + theme (model writes real copy, engine guarantees legibility), but every DATA-bound or LINK-bound widget (countdown date, weather location, menu→POS, CTA→action, QR→url, logo→asset) lands as a hardcoded placeholder because (a) the ArtDirectorSpec contract has no fields for these values and (b) the generation path never gathers tenant context (address, logo, POS connection, event dates) beyond brand colors. This is exactly what the template agent must learn to gather + emit.
