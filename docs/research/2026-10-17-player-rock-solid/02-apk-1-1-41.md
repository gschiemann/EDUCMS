## 1. One compositing contract (plan §4A, amended)

Every white or hazy screen in the field was a native surface drawn **under** a WebView forced
**transparent** (`layer=under_window` in every failing stop line). This build removes that
mechanism for every kind of native session rather than guarding it.

| Change | Where | What it does now |
|---|---|---|
| WebView opaque black, always | `FaceVideoBox.commit`, `FaceVideoBox.stopSession`, `SharedVideoBox` | Every `setBackgroundColor(Color.TRANSPARENT)` on a WebView is gone. `commit` re-asserts BLACK; `stopSession` re-asserts BLACK **unconditionally** (the old restore was gated on "no other live session"). The only TRANSPARENT left is the surface's own container view. |
| Above the window or not native | `SoloVideoLayer` | `Mode` is `{DYNAMIC_ABOVE, STATIC_ABOVE}`; `UNDER_WINDOW` is no longer a mode. `mode(protocol, face, sdk)`: a **solo** on SDK ≥ 30 → dynamic (either face), on SDK 24–29 → static **on any hardware** (.40 limited static to Rockchip and left every other legacy box under the window); a **positioned slot** → static on every SDK. `Phase.UNDER_WINDOW` stays as the *prepared, not yet shown* phase so the dashboard's `layerMode` wire names are unchanged. |
| Positioned slots (protocol 3) on the same contract | `FaceVideoBox.attachSurface` / `boxRect` / `play` / `updated` | A slot's SurfaceView takes `setZOrderOnTop(true)` at creation (its layer is the static shape), is parked **beyond the physical display** by the same display-aware `parkingLeft` rule as the static solo (no longer merely right of the WebView) with its held first frame rendered there, and at `play` is moved onto its rect in the **same UI pass** that supersedes the on-glass session it covers and releases the clip. No hole, no transparency: the WebView is never touched for a slot. The interval histogram counts a slot's callbacks once it is on glass; `layerMode` reports `queued` (parked) / `above_window` / `retired` for a slot. |
| The one limitation, documented | `native-video-items.ts`, `nativeZones.ts`, `page.tsx` | Nothing of the page can draw **over** a native slot. So (1) a template VIDEO zone that **any** other zone overlaps — above or below it in the template — stays web: the API no longer lists it (`nativeTemplateVideoZones`, any-overlap rule replaces the old lower-zone rule), and the page refuses it again from its own geometry and logs `PLAYER_NATIVE_VIDEO_FALLBACK reason=zone-overlap next=stay` once; (2) transitions between native items are **hard cuts** handed over by the held first frame: the next slot's parked frame takes the rect in the native pass that removes the one it covers (`superseded`), and a slide leaving the glass stops its session at once (no linger behind the next slide's fade). |
| Refusal with a stable reason | `DeviceClassPolicy.refusal`, `FaceVideoBox.begin` | A session this box cannot compose above the window (a Taurus, an unhosted face, protocol 1) is registered and immediately stopped with `composition-unavailable`, **before** the emergency / lifecycle checks and before any network, surface or decoder. A refused session never uploads diagnostics. `protocol3-disabled` no longer exists. |
| Pair engine (protocol 1) refused | `SharedVideoBox.prepare` | It drew beneath the WebView and needed it transparent. It now answers `failed` + `composition-unavailable` before any work; its decode pipeline is removed; state / stop / emergency paths keep answering. The page's protocol-1 controller treats a failed state as one attempt and stays web. |
| Emergency path unchanged | `DisplayEmergency.enforceNow` → `SharedVideoHost.suppressForEmergency` → `FaceVideoBox.suppress("emergency-held")` → `stopSession` | Every elevated surface (solo or slot) is hidden (`GONE`) and removed synchronously when the hold runs on the main thread; the WebView is set VISIBLE **first** (experiment 1 can never leave it hidden under an alert) and BLACK last. |

Web hand-off for a slot (`NativeZoneVideo.tsx`, `nativeZones.ts`): the web element stays mounted
until native holds the first frame and the slot is on glass; `play` is then sent **with the web
element still mounted**; the children unmount only once native reports the slot on its rect
(`revealed`: `held` false after play), hidden under the native picture — nothing black is painted
in between. `protocol` (an APK without protocol 3) and `zone-overlap` are web-for-the-document
verdicts (`stay`): never retried, never a 24-hour block of the file (the block store is shared
with the solo engine).

Owner rules folded in: native is ON for every class with a hardware AVC decoder and the web engine
is the automatic fallback on a refused or failed session (`nativeSolo = protocol3 = soc != NOVASTAR`);
the update path has **two** values because the Manager is never device owner (no DevicePolicyManager
read is left in the table). SoC comes from any of `Build.HARDWARE/BOARD/MODEL/DEVICE/PRODUCT/
MANUFACTURER` (Rockchip: `^(rk[0-9]|rockchip)`; Amlogic: `amlogic` or a `t9xx/s9xx/sc2/a311d/t7/t5`
prefix, e.g. the fleet's `t982_ar301` board; NovaStar is checked first because a Taurus is a
Rockchip too, reusing `LedCanvas.isPosterClass`). The WebView major comes from
`WebViewCompat.getCurrentWebViewPackage`. `qualified` is `null` for every class: nothing is
qualified on this contract until Tuesday's glass says so. The resolved class is reported as
`device` on every `sharedVideoState` reply (`class, fleet, soc, sdk, webviewMajor, nativeSolo,

per process as `PLAYER_DEVICE_CLASS …`, copied into telemetry by the web reader
(`lastVideoReport.native.device`) and accepted by the API schema. Enrolment itself (which screens
the API hands a descriptor to, `PLAYER_NATIVE_VIDEO`) is the server's half of plan §4C and is not
in this PR.

## 3. Measurement that cannot lie (plan §4E, Astra STAB-01), `NativeVideoTiming.kt`

- **Interval histogram** (`RenderIntervalHistogram`): the deltas between consecutive unique
  `onFrameRendered` `nanos` stamps, counted once the surface is confirmed on the glass (solo:
  `ABOVE_WINDOW`; slot: on its rect). 16 buckets centred on k × P/4: at 30 fps bucket 2 ≈ 17 ms,
  **bucket 4 = 33.3 ms ± 4.2 ms** (the §7 gate), bucket 6 ≈ 50 ms, bucket 8 = 2P (a compositor-side
  drop), bucket 0 < 4 ms (duplicate callback), bucket 15 ≥ 3.6 P. The judder Greg sees shows as a
  bimodal 2/6 pattern while the mean reads 33.35 ms (that case is a unit test).
- **Display facts in every snapshot** (lead's field note, 2026-10-17: overlay vs GPU composition is a
  candidate for the M43's late-frame residue): `refreshRate` and `displayMode`
  (`modeId:WxH@Hz` of the SurfaceView's `Display.getMode()`) are read **live** on every state poll,
  every ledger entry and every buffer-sample line, so a change by experiment 2 or by the panel is
  visible when it happens.
- **Counters**: the existing decoded/submitted/late plus `droppedFrames` (the pump's drops) in the
  same `timing` block.
- **Persisted ledger** (`NativeTimingLedger`): SharedPreferences `native_video_timing`, a queue of
  the last 6 session summaries with an explicit `overflow` count, a `live` checkpoint written once
  a minute while a session presents, and recovery of an unclosed checkpoint as its own entry on
  the next boot. Every entry carries Android's `BOOT_COUNT`; a recovered checkpoint from another
  boot is `reason: device-rebooted` (the fleet's panels reboot nightly on an OEM schedule), from
  the same boot `process-ended`; both `recovered: true`. A fresh session cannot erase it. Every
  entry is stamped `at` (wall clock, when it happened) and `uptimeMs`. Reported as `timing.history`;
  `PLAYER_NATIVE_VIDEO_STOP` lines now carry `drops`, `intervals` and `onPeriod`.
- **PixelCopy buffer samples, read right** (`NativeVideoSurfaceProbe`): on the M43 every sample in
  the first 10 s after reveal, and sometimes at 60 s, read a uniform Y=0/U=0/V=0 buffer while frame
  callbacks advanced; the L55VEC (same board) read a real picture from frame 2. A copy result other
  than SUCCESS, or a perfectly uniform buffer, is now reported as `readable=false …
  note=not-readable-by-pixelcopy(overlay-plane?)` with the copy result code and `uniform=true|false`
  on every line — never as "green / black on the glass"; only the on-glass check can say that.
  Four samples per handoff: at reveal, +10 s, +60 s and **+5 min**.
- **Wire**: `apps/web/src/app/player/nativeSharedVideo.ts` copies only the known, bounded fields
  (unknown ones are dropped, never forwarded); `apps/api/src/telemetry/telemetry.schema.ts` accepts
  them (strict, bounded, exactly 16 buckets, ≤ 8 history rows); `telemetry.ts` holds the new keys
  back after an older API answers 400 (`videoExtrasRefused`, `withoutNativeExtras`), the same
  self-heal as the video extras. Deploy order: this PR's API before the field APK reaches a screen.

## 4. The three M43 experiments (plan §4E), default off

API: `PLAYER_NATIVE_VIDEO_EXPERIMENTS` (Railway env), comma tokens `webview-invisible:<screen uuid|all>`,
`surface-frame-rate:<…>`, `decoder-rotation:<…>` (`apps/api/src/screens/native-video.ts`). The flags
ride on the hashed `nativeVideo` descriptor as `experiments: { webviewInvisible, surfaceFrameRate,
decoderRotation }` — **omitted when none is on** (nobody else's payload hash moves) and **outside
`revision`**: flipping a flag changes the manifest (ETag) but never restarts a session that is
presenting; it applies to the next native session (content change, reload, REFRESH_WEB). The APK
parses the object fail-soft (anything but JSON `true` is off; unknown keys ignored). The
experiments apply to the solo engine; a slot is never hidden under them.

| # | Experiment | APK | Never blanks because |
|---|---|---|---|
| 1 | `webviewInvisible` | On the frame that confirms `ABOVE_WINDOW`, `host.web.visibility = INVISIBLE`. VISIBLE is restored as the **first** statement of `stopSession`'s view pass — on any end, and synchronously on an emergency hold. | A process-wide guard (`NativeExperimentGuard`) switches the experiment off for the rest of the process after one end the hidden page could have caused (`page-lease-expired`, `output-stalled`, `output-unavailable`, `codec-stalled`): one visible flip at most, never a storm. Reported under `experiments.guard`. |
| 2 | `surfaceFrameRate` | `Api30SurfaceFrameRate` (symbol-isolated, API 30+): `Surface.setFrameRate(fps, FIXED_SOURCE, CHANGE_FRAME_RATE_ONLY_IF_SEAMLESS)` on the SurfaceView's surface before the decoder is configured (API 30's two-argument form is ONLY_IF_SEAMLESS by definition). Result (`only-if-seamless` / `refused`) and the display mode are logged (`PLAYER_NATIVE_VIDEO_EXPERIMENT name=surfaceFrameRate …`). | The display changes rate only if it can do so without a mode switch. |
| 3 | `decoderRotation` | No APK orientation logic changed. The page (`nativeOrientationRequest`) asks the existing `setOrientation` bridge method for the value `NATURAL` when the descriptor carries the flag and the manifest orientation is not AUTO; `MainActivity.applyOrientation` maps it to `SCREEN_ORIENTATION_NOSENSOR` (persisted like the others). The page's existing body-rotation fallback lays the web content out; `SharedVideoTransform.degrees` already derives the decoder rotation from the window shape. An older APK logs "unknown value" and keeps what it had. No new bridge method (rule 9). | `configChanges` already covers orientation, so the window re-lays out without an Activity restart; the flip is a one-time relayout at manifest apply, before a native session starts. |

**What to expect on Tuesday if experiment 1 is on:** an INVISIBLE WebView makes Chromium treat
the page as hidden, which throttles its timers (intensive throttling after ~5 min on Chrome 88+).
The native lease is renewed by the page's 500 ms poll; if throttling stops the poll, the session
ends with `page-lease-expired`, the WebView comes back, the web player takes over, and the guard
disables the experiment for the process. That is exactly the one-flip-then-stay bound; the lead
should read `experiments.guard.disabled` on the state before judging the counter clip.

## 8. Risks and limits the lead should know

1. **Static-above on non-Rockchip SDK 24–29, dynamic-above on a Presentation face (face 1,
   SDK ≥ 30), and every positioned slot above the window are unqualified.** .40 only ran static on
   Rockchip, dynamic on face 0, and slots under a transparent WebView; the contract now covers
   every class and both kinds of session. Nothing in the fleet is an Android 11+ double-sided
   unit; the Android 9 Commercial panels (G24, FUH43) are the one class that moves from
   under-window to static-above — they are not enrolled in native today (`PLAYER_NATIVE_VIDEO`),
   so this is inert until the lead enrols one.
2. **Slots are hard cuts.** A native item's last frame cannot linger behind the next slide's fade
   and nothing of the page can draw over a native zone; overlapped zones stay web. If the owner
   later wants widgets over video, that is a different contract (a transparent WebView), not a
   switch.
3. **The protocol-1 pair engine is gone as a working path.** `PLAYER_NATIVE_DUAL_VIDEO` is empty
   in production; a page that still asks gets a stable refusal and plays web.
4. **Experiment 1 and page visibility** (§4): expect timer throttling; the guard bounds it to one
   flip. The 15-second emergency HTTP backstop poll is also a timer; the WebSocket OVERRIDE path
   is not throttled. Judge it with the counter clip and the guard state, not the counters alone.
5. **A flag flip during a native download** re-proves the selection after the download
   (`fresh == d` now includes the flags) and ends that attempt as `selection-changed`, a transient
   that retries in 30 s. Harmless, mentioned for log reading.
6. **Registration vs. delivery.** The registry entry is committed here; the private mirror
   object `apks/field-player/<sha256>.apk` must be uploaded with the service-role key (the lead's
   step, as for .40) before `PLAYER_APK_FIELD_*` can deliver it. The CI artifact's digest is the
   authority; the mirror's bytes must hash to it.
7. **Not touched:** the Manager, the server-side enrolment table (`PLAYER_NATIVE_VIDEO` stays the
   switch), the interruption gate and ledger, the demotion sampler, the wedge detector.
