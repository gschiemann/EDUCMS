# Recon: Tenant hierarchy creation

## Summary
District→school hierarchy is a self-referential Tenant tree: `Tenant.parentId` → parent Tenant (relation "TenantHierarchy", schema.prisma:14,71-72). Top-level tenants are created by `POST /api/v1/signup` (OnboardingService.signup — creates Tenant + first DISTRICT_ADMIN user + audit row in one transaction); child schools/locations by `POST /api/v1/tenants/children` (DISTRICT_ADMIN/SUPER_ADMIN, slug auto-derived from name). The canonical seed pattern to copy is `packages/database/prisma/seed-multilocation-demo.mjs` (+ `seed-50-locations.mjs` for scale): fixed-UUID upserts of a parent + N child tenants with vertical/address/lat/lng, an argon2id-hashed DISTRICT_ADMIN user, and screens created directly with `pairedAt: now` + unique `deviceFingerprint` — which bypasses license enforcement entirely because seat checks only live in the `/api/v1/screens/pair` API path. With no License row a tenant is "PILOT" tier with seatLimit = env `PILOT_SEAT_LIMIT` (default 1000), so ~40 seeded screens are unblocked unless someone sets PILOT_SEAT_LIMIT=3.

═══ 2. API ENDPOINTS FOR TENANT CREATION ═══
No DTO classes — plain @Body() inline-typed objects, manual validation.
A) Top-level tenant (district/org): POST /api/v1/signup (onboarding.controller.ts:23 → OnboardingService.signup, onboarding.service.ts:66-208). Body: { districtName (required), slug?, adminEmail (required), password (required, 8-200 chars), vertical? (default 'K12', validated isVertical), firstName?, lastName?, phone?, address?, latitude?, longitude? }. Slug: slugify(input.slug || districtName) = lowercase, [^a-z0-9]+→'-', trim '-', .slice(0,60) (onboarding.service.ts:30-37). Conflicts: 409 'That slug is already taken.' / 'An account with that email already exists.'. Transaction creates: tenant.create({name, slug, vertical, address, latitude?, longitude?}) + user.create({tenantId, email, passwordHash, role: AppRole.DISTRICT_ADMIN, status:'ACTIVE', firstName, lastName, phone}) + auditLog action 'TENANT_SIGNUP'. Then sendWelcome (non-fatal) + `void this.sampleData.seedForNewTenant(tenant.id, user.id, requestedVertical)` (auto sample data per vertical) + returns authService.login(user) (JWT).
B) Child school/location: POST /api/v1/tenants/children (tenants.controller.ts:98-173). Guards: JwtAuthGuard+RbacGuard, @RequireRoles(SUPER_ADMIN, DISTRICT_ADMIN), @Throttle 10/60s. Body: { name (required), slug? (back-compat override; normally derived), address?, latitude?, longitude? }. Slug gen (line 111): (body.slug || name).trim().toLowerCase().replace(/[^a-z0-9]+/g,'-').replace(/^-|-$/g,'').slice(0,60); must be ≥2 chars (400 TENANT_SLUG_TOO_SHORT); global-unique (409 TENANT_SLUG_TAKEN). parentId = callerTenant.parentId ?? callerTenant.id (a DISTRICT_ADMIN on a child creates siblings under the district, line 140). Coords stored only when BOTH lat (-90..90) and lng (-180..180) valid. Transaction: tenant.create + auditLog action 'CHILD_TENANT_CREATED' scoped to district. Returns { success:true, child:{id,name,slug,parentId,createdAt} }. NOTE: createChild does NOT create any user in the child, does NOT copy vertical from parent (child gets default 'K12') and does NOT actually inherit emergency settings despite the docstring.
Related: GET /api/v1/tenants/accessible (switcher list), GET /api/v1/tenants/children (list w/ _count screens+users), POST /api/v1/tenants/switch (re-issues JWT scoped to target tenant, 30d expiry), PATCH /api/v1/tenants/me (vertical/name/address/lat/lng), DELETE /api/v1/tenants/children/:id (blocked if children/screens/active-emergency/audit-history → archive instead), POST /api/v1/tenants/:id/archive + /:id/unarchive + /archive-bulk (SUPER_ADMIN only).

═══ 5. LICENSE / SEAT ENFORCEMENT — WILL NOT BLOCK ~40 SEEDED SCREENS ═══
License model (schema.prisma:571-603, table licenses): id, tenantId @unique, tier String (PILOT|STANDARD|ENTERPRISE|EDU_DISTRICT|RESTAURANT_CHAIN|custom), seatLimit Int @default(3), billingMode @default("CARD") (CARD|INVOICE|PURCHASE_ORDER|COMP), status @default("ACTIVE") (ACTIVE|PAST_DUE|SUSPENDED|CANCELLED), monthlyPriceCents Int?, stripeCustomerId/stripeSubscriptionId, currentPeriodStart/currentPeriodEnd/expiresAt DateTime?, notes, stripeLastEventCreatedAt, createdAt/updatedAt.
Enforcement (apps/api/src/license/license.service.ts): NO License row → tier 'PILOT', seatLimit = LicenseService.PILOT_SEAT_LIMIT = env PILOT_SEAT_LIMIT parsed (default **1000**, logged at boot; lines 42-61), status ACTIVE, no expiry. Seat counting = screen.count({ where: { tenantId, pairedAt: { not: null } } }) (usedSeats, line 99-104). assertSeatAvailable (lines 127-170) throws 402 LICENSE_INACTIVE / LICENSE_EXPIRED / LICENSE_EXHAUSTED. ONLY call site: POST /api/v1/screens/pair (screens.controller.ts:1251, inside SERIALIZABLE tx + withDbRetry) and only when isNewPair (screen.tenantId was null).
How seeded/demo tenants bypass: (a) seed scripts write Screen rows directly via Prisma with pairedAt set — the API pair path (and thus assertSeatAvailable) is never invoked, so there is NO enforcement at the DB layer at all; (b) even counting against the pilot ceiling, 40 screens << 1000 default. Only risk: if the deploy env sets PILOT_SEAT_LIMIT=3 AND you later try to pair MORE screens via the API for that tenant — seeded rows would already consume seats. Fix for a demo tenant if needed: create a License row { tenantId, tier:'ENTERPRISE' or 'COMP', seatLimit: 100, billingMode:'COMP', status:'ACTIVE' } — getEffective then uses License.seatLimit.
Also relevant: super-license.controller.ts:102 uses `t.license?.seatLimit ?? LicenseService.PILOT_SEAT_LIMIT` for the SUPER_ADMIN license overview.
Gotchas for a new seed script: (1) slug + email + deviceFingerprint are all globally unique — use deterministic prefixed values and upserts; (2) createChild API does NOT set vertical on children — set it explicitly in the seed; (3) manifest hot-cache: content edits via raw SQL lag 30 min on players — Prisma client writes are fine; (4) tenant hard-delete impossible once auditLog rows exist — build a --clean mode that deletes auditLog rows for the demo tenant ids first (as seed-multilocation-demo.mjs clean() does) or use archive.
