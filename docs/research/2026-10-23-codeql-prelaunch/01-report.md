## The one that was real

**#76 — apps/web/public/celebrations/deck.html: reflected DOM XSS on the dashboard origin.** The cue index did `idx.innerHTML = … '<a href="?cue=' + k + '&team=' + q.get('team') + '">'`. The file is a static asset on the web origin, so it is same-origin with the dashboard, and the matcher in apps/web/src/proxy.ts deliberately excludes celebrations/ from the nonce CSP (static boards get no CSP header). A link `/celebrations/deck.html?team="><img src=x onerror=…>` therefore ran attacker JS on the dashboard origin — enough to call the same-origin session BFF (/api/session/*) for an access token, i.e. operator takeover from one link click. Fixed by building the index from DOM nodes (createElement / textContent) and encodeURIComponent-ing every query value. The same file's ?cue=__proto__ prototype pollution (#2044–#2048) is closed by a hasOwnProperty lookup and working on an own-property copy.

Everything else fixed is hardening of a path that already had a stronger control behind it (details in the table): a weak PRNG for sample webhook secrets, two quadratic regexes on device/CSV input, three entity decoders that double-decoded `&amp;lt;`, a CSS attribute-selector escape that missed the backslash, a regex built from CLI args, and HTML strip passes that could be rebuilt by a split tag (`<scr<script></script>ipt>`) or a junk end tag (`</script foo>`).

## Static boards (public/templates/*, public/holiday-templates/*) — 2,272 alerts, deliberately left open

Not dismissed, per instruction. Rationale for whoever triages them:

- Every board is a self-contained HTML document rendered in `<iframe sandbox="allow-scripts">` with **no allow-same-origin** (null/opaque origin — WidgetRenderer.tsx, HolidayWidget.tsx, the templates gallery, the kiosk shell). Script in that document cannot read the dashboard's cookies, storage, DOM or the device token, cannot navigate the top frame (no allow-top-navigation) and cannot open popups that escape.
- The boards' own scripts (the baked EDUCMS-SHIM-V15 / _edit-shim.js, menu applyMenu(), board-media-controls) accept postMessage only from window.parent and read operator overrides from the builder; the CodeQL findings are selector/attribute string building, innerHTML of board-authored content and single-character quote escapes — all inside that sandbox.
- The AI designer boards additionally pass buildSafeDesignerSrcdoc / wrapDesignerSrcdoc at render time (now fixpoint strips, PR #139) under default-src 'none'; script-src 'nonce-…'.
- The right fix for the class is mechanical and board-wide (re-inject a shim that uses textContent and a CSS-string escape, then regenerate posters + exemplars + POSTER_VERSION); it must not be done as 2,272 individual dismissals. Until then they are contained by the sandbox, not by the regexes.
