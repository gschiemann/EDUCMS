## Lens: canvas-manipulation

The canvas is closer to Canva than expected — marquee + shift-click multi-select with group move (BuilderCanvas.tsx:320-477), labeled snap guides to zone edges/centers + canvas center (snap-engine.ts), all 8 resize handles (BuilderZone.tsx:71), cmd-D/C/V, arrow nudge with Shift/Alt steps, lock, z-order, 50-deep undo, and a shortcuts modal all exist and work. What kills the 'feels like Canva' sensation is (1) the default 5%-grid quantization that makes every drag chunky AND defeats the element-snap engine, (2) multi-select collapsing the moment you grab a resize handle (no group scale), (3) zero right-click context menu, (4) no alt-drag duplicate, (5) no shift aspect-lock / alt from-center resize modifiers, and (6) no equal-spacing/measurement guides or distribute. None of these need a new setting — they're all default-behavior and modifier-key fixes. Rotation, wheel-zoom/space-pan, and group/ungroup are the second tier. The store model (selectedIds: string[], updateZones batch patcher, beginTransaction) is already multi-select-ready for nearly all of it; only persistent grouping needs a Zone model field.

### [P0] Default grid-snap quantizes every drag to 5% steps and largely defeats the element-snap guides _(effort S)_
- **Today:** snap-engine.ts:49-52 snaps x/y to the grid whenever the grid is VISIBLE (snapGrid: showGrid passed at BuilderCanvas.tsx:390-394), and store defaults are showGrid: true + gridSize: 5 (useBuilderStore.ts:156-159, constants.ts:553). So out of the box every drag moves in 5%-of-canvas jumps (~192px on a 4K design), and because element snapping then runs on the already-quantized position with a 1.5% threshold (constants.ts:555, snap-engine.ts:71-81), a neighbor edge/center at any non-multiple-of-5 position is unreachable — the beautiful labeled guide system (BuilderCanvas.tsx:637-689) rarely fires. snapResize has the same coupling (snap-engine.ts:118-124). This is the single biggest tactile difference vs Canva: dragging feels steppy, not fluid.
- **Canva:** Canva never quantizes pointer movement to a grid by default — dragging is 1:1 fluid and magenta guides snap to neighbors/canvas as you pass them; grid/rulers are a visual overlay only.
- **Fix:** Decouple 'grid visible' from 'movement quantized': make dragging follow the pointer 1:1, run element/canvas snapping on the raw position, and treat grid lines as just another snap TARGET (within the same 1.5% threshold) instead of a pre-quantizer. No new setting — the existing Grid/Magnet toggles keep their meaning, the default just stops fighting the operator.

### [P1] Grabbing a resize handle collapses multi-select — no group resize/scale _(effort M)_
- **Today:** onResizePointerDown does select([zoneId]) unconditionally (BuilderCanvas.tsx:355-363), so the moment an operator with 4 zones selected touches a handle, the selection collapses to one zone and only it resizes. Multi-select group MOVE works (move branch uses updateZones over dragState.origs, BuilderCanvas.tsx:379-401), and the store is fully ready (selectedIds: string[] + updateZones batch patcher, useBuilderStore.ts:46,551-558) — only the resize path is single-zone.
- **Canva:** Canva draws one bounding box around a multi-selection with corner handles that proportionally scale every selected element's position and size together.
- **Fix:** When selectedIds.length > 1, render a selection bounding box with corner handles; on drag, compute the scale factor of the box and apply it to each zone's x/y/w/h relative to the box origin via the existing updateZones patcher. No UI addition beyond the box that operators already expect.

### [P1] No alt/option-drag to duplicate _(effort S)_
- **Today:** onZonePointerDown reads shiftKey/metaKey/ctrlKey only for additive selection (BuilderCanvas.tsx:336-353); altKey is never checked anywhere in the drag path, so alt-dragging a zone just moves it. duplicateZone() already exists in the store (useBuilderStore.ts:516-532) — it's only reachable via cmd-D or a button.
- **Canva:** Alt/option-drag peels off a copy in place and drags the copy — the fastest repetition gesture in every design tool, used constantly for menu rows, sponsor logos, stat tiles.
- **Fix:** In onZonePointerDown, if e.altKey: call duplicateZone(id) for each selected zone first, then start the move drag on the new copies. Pure gesture, zero UI.

### [P1] No shift aspect-lock or alt resize-from-center modifiers _(effort S)_
- **Today:** The resize branch of the drag effect (BuilderCanvas.tsx:402-418) applies raw dx/dy per handle with no e.shiftKey or e.altKey handling — a corner drag on a logo or image zone freely distorts the box, and there is no way to resize symmetrically around center. All 8 handles exist (BuilderZone.tsx:71) so the surface is ready.
- **Canva:** Canva locks aspect ratio on corner handles by default for media, shift toggles the lock, and alt resizes from center — muscle memory shared with Figma/PowerPoint/Illustrator.
- **Fix:** In the resize pointermove: corner handles on IMAGE/LOGO/VIDEO zones keep aspect by default (shift releases it; other widgets get shift = lock), alt mirrors the delta around the zone center. Modifier keys only — no setting, matches every tool the operator already knows.

### [P1] No right-click context menu anywhere on the canvas _(effort M)_
- **Today:** There is no onContextMenu handler in the entire template-builder directory (verified by grep; the canvas root at BuilderCanvas.tsx:543-559 handles onPointerDown/onDragEnter only), so right-click shows the browser's default menu. Every action it would carry already exists in the store — duplicateZone, removeSelected, moveLayer up/down/top/bottom, toggleLock, copy/paste clipboard (BuilderShell.tsx:471-514, useBuilderStore.ts:593-620) — but they're scattered across keyboard shortcuts, the bottom bar, and the Layers panel.
- **Canva:** Right-click on any element opens copy/paste/duplicate/delete/layer-order/copy-style — it's the primary discovery surface for canvas actions and a huge 'this is a real design tool' signal.
- **Fix:** Add an onContextMenu on zones and canvas that opens a small menu wired to the existing store actions (Duplicate, Copy/Paste, Delete, Bring forward/Send back/To front/To back, Lock, Copy style). Pure re-exposure of shipped actions — nothing new to build in the store.

### [P1] Snap engine has no equal-spacing hints, no pixel-distance labels, no canvas thirds _(effort M)_
- **Today:** collectTargets only emits canvas 0/50/100 plus other zones' edges and centers (snap-engine.ts:6-23) — no rule-of-thirds lines and no 'gap between A and B equals gap between B and C' spacing detection. The guide-label code explicitly acknowledges the gap: 'Canva shows pixel offsets between elements; we'd need both end positions to compute that, so percent-of-canvas is a clean v1' (BuilderCanvas.tsx:639-655) — labels show raw percentages like '37.5%', which mean nothing to an operator.
- **Canva:** Canva shows pink equal-gap badges when spacing matches between neighbors, snaps to those equal-spacing positions, and displays real distance measurements between the dragged element and its neighbors.
- **Fix:** Extend collectTargets with (a) canvas 33.3/66.6 thirds and (b) equal-gap candidates computed from pairs of aligned neighbors, and convert guide labels from percent to real pixels using meta.screenWidth/Height (already in the store). The dragging operator gets 'even spacing' for free — no toggle.

### [P1] No distribute-evenly action; single-zone align buttons buried in a collapsed panel section _(effort S)_
- **Today:** MultiAlignButtons offers Left/CenterX/Right/Top/CenterY/Bottom only (PropertiesPanel.tsx:2011-2039) — there is no distribute-horizontally/vertically for 3+ zones, so evenly spacing sponsor logos or menu rows is manual math. The single-zone align-to-canvas buttons (PropertiesPanel.tsx:821-827) sit inside the Geometry CollapsibleSection which is hidden by default (PropertiesPanel.tsx:1409-1418 'hidden by default, one click to open').
- **Canva:** Canva's Position panel has Align + 'Space evenly' (tidy up) one click away, and it also auto-tidies via the equal-spacing smart guides during drag.
- **Fix:** Add two Distribute buttons (H/V) to the existing MultiAlignButtons grid — sort selected zones by x (or y) and space the gaps equally via the existing updateZones batch patcher; show the same align/distribute cluster in the floating selection context (bottom bar) when 2+ zones are selected instead of only deep in the right panel.

### [P2] Rotation exists only as a hidden panel field — no on-canvas rotation handle _(effort M)_
- **Today:** Zone rotation shipped in the §19 wave as defaultConfig._zoneRotation applied via transform: rotate() (BuilderZone.tsx:367-380) and is edited numerically in PropertiesPanel — but the HANDLES array is the 8 resize handles only (BuilderZone.tsx:71); there is no grab-and-turn affordance, and the snap engine + marquee hit-test (BuilderCanvas.tsx:464-466) operate on the unrotated rect.
- **Canva:** Canva shows a rotate handle below every selected element with a live degree badge and snaps at 0/45/90; rotation is a direct-manipulation gesture, never a number field.
- **Fix:** Add a rotate handle beneath the selection outline that writes _zoneRotation through the existing updateZone path, snapping to 15-degree increments near cardinal angles (release with a modifier for free rotation). The persistence + render path already exists — this is only the gesture.

### [P2] No wheel/pinch zoom, no space-drag pan, no zoom keyboard shortcuts _(effort M)_
- **Today:** Zoom is only reachable via preset stepper buttons in the bottom bar (BuilderShell.tsx:1541-1570, presets 0.25-3) and setZoom in the store (useBuilderStore.ts:633); there is no onWheel handler, no pinch support, and no space-drag pan anywhere in BuilderShell/BuilderCanvas (verified by grep) — panning while zoomed relies on the overflow-auto scrollbars of the wrapper (BuilderCanvas.tsx:499). cmd+= / cmd+- / cmd+0 are absent from the keyboard handler (BuilderShell.tsx:427-529). To be fair, zoom=1 IS a fit-to-viewport baseline (BuilderCanvas.tsx:527-533), so 'fit' exists.
- **Canva:** Ctrl/cmd+scroll and trackpad pinch zoom toward the cursor; space-drag pans; cmd+0 fits, cmd+1 goes to 100%.
- **Fix:** Add ctrl/cmd+wheel (and pinch ctrlKey wheel events) zoom-to-cursor on the canvas wrapper, hold-space-to-pan, and cmd+0/cmd+= /cmd+- in the existing keyboard handler — all writing through the existing setZoom. Gestures only, no new chrome.

### [P2] No group/ungroup and no cmd-A select-all _(effort L)_
- **Today:** The Zone model has no group field (types.ts:70-90) and the store has no group actions, so operators can't bind a headline+logo+stat cluster into a unit that moves/duplicates together across edits — every re-selection is a fresh marquee. cmd-A is also absent from the shortcut handler (BuilderShell.tsx:427-529; shortcuts modal list at 1640-1656 confirms). Selection is array-based (selectedIds, useBuilderStore.ts:46) so transient select-all is a one-liner; persistent grouping needs a groupId on Zone + click-resolution to the group.
- **Canva:** cmd-G groups a selection into a unit that selects/moves/scales as one (double-click enters it), cmd-shift-G ungroups, cmd-A selects everything.
- **Fix:** Ship cmd-A immediately (select all zones on the active scene). For grouping: add an optional groupId to Zone (additive schema), make click select the whole group with double-click drilling in, and put Group/Ungroup in the new right-click menu — leaning on the already-working batch move (updateZones) so groups need no new drag code.


## Lens: inline-text-editing

The React-zone architecture is already Canva-grade in structure and must NOT be re-flagged: one-click on-canvas contentEditable editing shipped (BuilderZone.tsx enterFieldEdit :222-350 with dotted-path commit, drag-vs-edit threshold, Escape revert), 109 widget files expose data-field hotspots, and a persistent bottom bar (BuilderShell.tsx BuilderBottomBar :831+) gives per-field font/size/B-I-U-S/color synced two-way with canvas clicks and panel focus via the template-edit-field event, plus Cmd+B/I/U shortcuts and a field/zone/template scope selector. The AI-designer srcdoc path also verified: typing in the panel live-updates the board per keystroke via educms-overrides postMessage with no reload (WidgetRenderer.tsx:3828-3847) — that's what the phase-4b demo was. SINGLE BIGGEST CHANGE PER ARCHITECTURE: (1) React zones — make the font system real: ~13 of the pickers' fonts are never loaded so picking them silently renders OS fallback (the #1 'editing feels broken' signal), then one searchable in-face font menu with brand fonts pinned; (2) EXTERNAL_HTML boards — kill the per-keystroke iframe remount (key={srcWithOverrides} reloads the full 4K document on every character typed; switch live edits to the postMessage path the shim already listens for — the srcdoc path proves it works); (3) AI-designer boards — in-place contentEditable typing via a shim V7 (the shim already owns the DOM inside the sandbox and the outbound message channel; today it only reports clicks). Word-level rich formatting (RICH_TEXT is a plain-text costume) and shadow/outline legibility effects are the two genuine capability gaps vs Canva; everything else is polish on an already-shipped foundation.

### [P0] Every keystroke fully reloads the board — URL-based EXTERNAL_HTML editing is remount-per-character _(effort S)_
- **Today:** apps/web/src/components/widgets/WidgetRenderer.tsx:3884-3886 renders the ~107 EXTERNAL_HTML boards with key={srcWithOverrides} src={srcWithOverrides} ('key on the full overrides URL so any edit reloads the frame'). srcWithOverrides (3738-3786) base64-bakes textOverrides into the URL, and the panel's TextField fires onChange on every keystroke (PropertiesPanel.tsx:7263 → setOverride:7024 → setField). Chain has zero debounce: one character typed → new config → new URL → React remounts the iframe → the full 3840×2160 document re-fetches, re-runs fonts/auto-fit/animations, and flashes. The srcdoc AI-designer path already solved this — postDesignerOverrides (WidgetRenderer.tsx:3828-3847) pushes the SAME educms-overrides postMessage the shim listens for, updating text live with no reload.
- **Canva:** Canva text editing is in-place and zero-flicker; the canvas never reloads while you type.
- **Fix:** Make the URL path do what the srcdoc path already does: on config change, postMessage {type:'educms-overrides', text, textStyles, img} into the live iframe (the V5/V6 shim's message listener already applies it — inject-shim-v2.cjs:135), and drop textOverrides/textStyles/img from the iframe key so typing never remounts. Keep URL params only for first paint and the player. Zero new UI, pure friction removal — typing feels instant like the AI boards do today.

### [P1] No in-place typing on EXTERNAL_HTML or AI-designer boards — shim reports clicks but can't take a keystroke _(effort M)_
- **Today:** The shim's armEdit (apps/web/scripts/inject-shim-v2.cjs:130 and the verbatim EDUCMS-SHIM-V6 copy in apps/api/src/ai/designer-edit-shim.ts:15) only does hover-outline + click → postMessage educms-field-click; the panel scrolls/focuses the matching input (PropertiesPanel.tsx:6948-6967) and ALL typing happens in the side panel. The shim runs inside the allow-scripts sandbox with full DOM access — it could flip the clicked [data-field] to contentEditable exactly like BuilderZone.enterFieldEdit already does for React zones (BuilderZone.tsx:234-350), but no such path exists. Memory's 'typed into a live board's field' (phase 4b) was typing in the PANEL with live board update — verified: that shipped; on-board typing did not.
- **Canva:** Double-click text → cursor appears ON the design → type. This is Canva's core magic and the benchmark Greg is comparing against.
- **Fix:** Shim V7: on click in edit mode, set contentEditable on the [data-field] node in-place (caret on the board, text selected), commit on blur/Enter via a new outbound message {type:'educms-field-input', key, value} that the panel writes into textOverrides; Escape reverts; panel remains as fallback + styling home. One source (inject-shim-v2.cjs + designer-edit-shim.ts share the block), then re-run the injectors per the CLAUDE.md redesign invariant. This is THE single biggest Canva-parity change for architectures 2 and 3.

### [P1] Font pickers sell ~13 fonts that are never loaded — picking them silently renders an OS fallback _(effort S)_
- **Today:** BOTTOM_BAR_FONTS (BuilderShell.tsx:821-826) offers Roboto, Open Sans, Lato, Raleway, Nunito, Source Sans Pro, Merriweather, Bebas Neue, Pacifico; FONT_OPTIONS (PropertiesPanel.tsx:7491-7509) adds Permanent Marker, Indie Flower, EB Garamond, VT323, Press Start 2P. ### [P1] Per-field size stepper anchors at 16px inside iframe boards — tapping '+' shrinks a 120px headline to 18px _(effort S)_
- **Today:** BuilderShell.tsx:1034-1043 measureFieldFontSize queries [data-field] in the PARENT document, but EXTERNAL_HTML and AI-designer fields live inside a null-origin sandboxed iframe — unreachable, so it returns null and the stepper falls back to 16 (BuilderShell.tsx:1145 '(curFieldStyle.fontSize ?? fieldMeasured) || 16'). - **Fix:** Have the shim self-report: include getComputedStyle(el).fontSize (plus color/family) in the educms-field-click payload — the shim runs inside the iframe and can measure freely. Panel stores it as the anchor for the stepper. One field added to an existing message; no UI change.
