## Findings

**[P2] Device re-register busts the entire manifest cache — fleet boot storms neutralize the egress diet — NEW.** `POST /screens/register` writes `resolution, osInfo, browserInfo, userAgent, ipAddress, lastPingAt, status, hardwareModel` on every hit for both paired (:505-520) and unpaired (:586-600) screens (`screens.controller.ts`). None of the identity fields are in `SCREEN_TELEMETRY_ONLY_FIELDS`, so each register → `bumpManifestContentRev()` → `manifestCache.clear()` (all screens, `manifest-hot-cache.ts:293-296`). The player calls register on every boot and retries at 2-30s backoff (`player/page.tsx:3702-3800`). Impact: bounded per-boot normally, but a district morning power-on or post-OTA re-register wave clears the whole cache repeatedly during the exact high-load window it exists for; steady-state, one flapping screen erodes the diet. (Pairing-phase polling rides the debounced heartbeat, not register — verified :3893+ uses `buildHeartbeatUrl`.) Fix sketch: for register writes, bust per-screen (`invalidateManifestCache(screenId)`) instead of the global rev, or extend `shouldBumpManifestRev` with a Screen "identity-only" field set. Neither register nor these columns appear in the bill-diet doc — this path was never enumerated.

**[P2] Crash-report endpoint busts the full cache; a crash-looping kiosk = 10 fleet-wide clears/min — NEW.** `POST /screens/status/:fp/crash-report` (`screens.controller.ts:1113-1150`, throttle 10/min/IP) writes `lastCrashAt/Source/Version/Message/Stack` — columns added 2026-04-27 (`054e437d`), absent from `SCREEN_TELEMETRY_ONLY_FIELDS`, none manifest-rendered. The 07-30 enumeration missed them. Failure mode couples "a device is crash-looping" with "manifest egress spikes fleet-wide". Fix: add the five `lastCrash*` columns to the telemetry set (safe — nothing in the manifest reads them).

**[P2] Emergency "never-evict" holds app-side only — player never requests persistent storage — NEW.** No `navigator.storage.persist()` anywhere in `apps/web/src` or `public/` (two methods: grep `persist()` in player page = none; grep `navigator.storage` web-wide = only `.estimate` at `player/page.tsx:2541`). Under disk pressure the UA may evict the origin's Cache Storage wholesale, emergency tier included, silently defeating the offline lockdown guarantee on a shared/low-storage device. One-line hardening at SW registration; the existing `estimate()` telemetry could also alert when `persisted === false`.

**[P2] bug-screenshots bucket: comment says "private (no public URL)", code creates `public: true` — NEW.** `bugs.controller.ts:1005-1030`. Screenshots capture the admin dashboard (tenant names, emails, console/network state). UUID paths make URLs unguessable (same posture as assets), but the stated intent and the shipped policy contradict — either flip to `public: false` + signed URLs on the bug view, or fix the comment and accept the posture explicitly.

**[P3] Cache-control dual-form invariant is one refactor from re-creating the egress bill — KNOWN-adjacent (documented, unmonitored per-object).** Server must send bare `max-age=N` (`supabase-storage.service.ts:386-394`), browser must send the full string (`AssetPicker.tsx:152-164`). Both sides carry warnings; nothing automated probes a freshly-uploaded object's served header (watchdog checks transport, not `cache-control`). Cheap hardening: assert `servedCacheControl` inside the watchdog probe cycle.

**[P3] Backfill + `deleteMany`/`extractPath` are hard-wired to the `assets` bucket** (`super-license.controller.ts:292` SQL `bucket_id = 'assets'`; `supabase-storage.service.ts:697-713,750-755`) — `branding-logos` and `bug-screenshots` objects can never be backfilled or bulk-wiped through these tools. Logos are tiny; note only.
