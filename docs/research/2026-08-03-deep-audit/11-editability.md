# §19 Editability audit — 2026-08-03

## Summary verdict

**Domain grade: A−.** This is no longer the 2026-05-26 "you can't edit a single word" surface. Every one of the 180 widget types the renderer dispatches reaches a real editor, via a four-stage fallback chain in `ContentFields` (`apps/web/src/components/template-builder/PropertiesPanel.tsx:2484` → hand-built case → `:6053` v2 registry auto-form → `:6286` MS/Fitness auto-form → `:6410` themed auto-form → `:6537` terminal `return null`). The panel is genuinely mounted (`BuilderShell.tsx:1215`, auto-opened on any selection change at `BuilderShell.tsx:283`), the dead `WidgetPalette.tsx` from the 2026-05-12 trap is **gone from the tree** (verified: `find apps/web/src -name "WidgetPalette*"` returns nothing), and there is a runnable RTL proof suite (`apps/web/src/components/template-builder/__tests__/editability-*.test.tsx`, 4 files) that mounts the **real** `ContentFields` — now gated blocking in CI (`.github/workflows/deploy-reliability.yml:142` `web-jest`).

**Widgets below B: 40** (35 D, 5 C) — all in one coherent hole: v2-pack variants registered under a canonical type that *already has a hand-built case*. Plus one content gap: 21 shipped holiday boards are unreachable.

## Findings

### [P1] F-2 — 40 v2 widget variants have *zero* typography, color, or background control anywhere in the product
**Evidence:** `apps/web/src/components/widgets/variants-register.ts:849–892` maps v2 categories onto canonical widget types. Nine of them (`'Announcements'→ANNOUNCEMENT`, `'Calendars'→CALENDAR`, `'Staff'→STAFF_SPOTLIGHT`, `'Countdowns'→COUNTDOWN`, `'Logos'→LOGO`, `'Weather'→WEATHER`, `'Bell Schedules'→BELL_SCHEDULE`, `'Clocks'→CLOCK`) point at types that **already have a hand-built `case`** in `PropertiesPanel.tsx`. Those cases `break` before ever reaching the v2 default branch at `:6053`, so the v2 Style section (`:6192–6276`) never renders. Then the universal text-style block is skipped for them too, because its guard is `!isV2Widget` (`PropertiesPanel.tsx:6576–6578`, where `isV2Widget = !!(cfg.variant && V2_BY_VARIANT_ID[cfg.variant])`). And the per-field bottom bar can't rescue it: **v2 widget files emit no `data-field` at all** — verified `grep -c data-field` = 0 for `v2/AnnouncementWidgets.tsx`, `CalendarWidgets.tsx`, `StaffWidgets.tsx`, `CountdownWidgets.tsx`, `LogoWidgets.tsx`, `WeatherWidgets.tsx`, `BellScheduleWidgets.tsx`, `ClockWidgets.tsx`, so `activeFieldName` never arms (`BuilderShell.tsx:1509`).
Counts from `apps/web/src/components/widgets/v2/registry.ts`: 5 variants per category × 7 text-bearing categories = **35 at D**; Clocks (5) keep `ColorField`+`bgColor` from their case (`:2908–2936`) but still lose font family/size/weight → **C**.
**Impact:** a district that drops the "Neon Alert" announcement (`ANN_NEON`, `registry.ts:242`) or "Bulletin Pin" onto a board cannot change its font, its size, its text color, or its background. Only the copy. This is the literal §19 criterion "Text addressable: content, font family, font size, font color, font weight" failing, on widgets that ship in the palette today. Below B ⇒ launch blocker by CLAUDE.md's own rule.
**Fix sketch:** the plumbing already exists and is proven — every one of those v2 files funnels `config.style` through `resolveStyle` (6 call sites each, verified). Two-line fix: in each of those 8 cases, before `break`, push the same `SHv2('style'…)` → `ColorPickerField`/`SelectField`/`AssetPickerField` block the default branch builds; **or** extract `:6192–6276` into a `v2StyleFields(cfg, setField)` helper and call it from the affected cases. Do **not** simply delete the `!isV2Widget` guard at `:6578` — the universal block writes zone-wide `cfg.fontFamily`/`cfg.color`, a different key space than `cfg.style`, so it would half-work and leave the background/accent/highlight controls still missing.
**NEW.**

### [P1] F-1 — 21 of 50 holiday boards are unreachable from the product
**Evidence:** `HolidayWidget.tsx:177–180` builds the iframe src as `` `/holiday-templates/${gradeLevel}-${variant}${suffix}.html` `` where `suffix` is only `''` or `'-portrait'`, and `variant` is constrained to the six keys in `HOLIDAY_VARIANTS` (`:140–146`). The 18 `*-v2.html` files and 3 `*-flagship.html` files in `apps/web/public/holiday-templates/` match no reachable path — e.g. `hs-christmas-flagship.html`, `es-halloween-v2.html`. The HOLIDAY properties case (`PropertiesPanel.tsx:4006`) exposes only two `SelectField`s (holiday + grade), no style/version picker.
**Two independent verifications** (absence rule): (a) enumerated all 50 files against the generated path set — 28 reachable, 21 orphans, 1 non-template (`_overhaul-gallery.html`); (b) repo-wide `grep -rn "christmas-v2\|christmas-flagship\|holiday.*flagship" apps/web/src apps/api/src packages` → **zero hits**. Nothing else routes to them.
**Impact:** paid design work that no operator can select; if `-flagship` is the intended upgrade, every customer is seeing the older board. Their bridges are intact (only `_overhaul-gallery.html` lacks `holiday:ready`/`holiday:schema`), so this is pure routing.
**Fix sketch:** add a third `SelectField` ("Board style": Classic / V2 / Flagship) writing `cfg.style`, and extend the `suffix` memo to `[styleSuffix, portraitSuffix].join('')` with an existence-gated option list. Or, if V2/flagship supersede the originals, rename them over the base files and delete the orphans.
**NEW.**

### [P2] F-3 — panel-focus vs canvas-click asymmetry on the MS / Fitness / themed packs (64 widget types)
**Evidence:** `PropertiesPanel.tsx:6314` `const isHsWidget = zone.widgetType.startsWith('HS_')` gates `StyleableField`/`StyleableAreaField`; everything else in the MS auto-form gets plain `TextField`/`TextAreaField` (`:6362–6394`), and the themed auto-form uses plain fields unconditionally (`:6507–6531`). Only `StyleableField` dispatches `template-edit-field` on focus (`:6792–6802`). The code comment at `:6306–6313` justifies this as "MS/Fitness widgets don't have the runtime `useTextStyleOverrides` hook … per-field styling would lie about what works" — but that reasoning is now stale: `useTextStyleOverrides` is only in the HS pack + `HolidayWidget` (20 files), while the *actual* application path is DOM-based CSS injection scoped to `[data-zone-id] [data-field="X"]` in **both** `BuilderZone.tsx:662,741` and `player/page.tsx:7176`. Every MS/Fitness/themed widget carries `data-field` (spot-checked: `MsArcadeWidget` 41, `FitnessIronWidget` 27, `AnimatedBellScheduleWidget` 5, `BulletinHallwayWidget` 10, `AnimatedWelcomeWidget` 9), so per-field styling *does* work for them — just only if the operator discovers it by clicking canvas text rather than the panel field.
**Impact:** alignment + line-height + brand-swatch color are the two §19 criteria not covered by the universal block, and they're hidden behind an undiscoverable gesture on 64 of the largest full-screen widgets. Not a blocker (the bar shows "Click any text on the canvas to edit its style", `BuilderShell.tsx:1790`), but it is the difference between B+ and A.
**Fix sketch:** drop the `isHsWidget` condition — use `StyleableField` for every auto-form key. It is a pure focus-tracker wrapping `TextField` (`:6816`); nothing else changes.
**NEW.**

### [P2] F-4 — COUNTDOWN missing the §19 "units shown" control; IMAGE missing "fill" + focal position
**Evidence:** `PropertiesPanel.tsx:2811–2907` — the COUNTDOWN case ships mode / label / target date+time / eyebrow / `staticDays` / prefix, but no days-hours-min-sec toggle, which §19 names explicitly. `:3824` — `fitMode` options are `[['cover','Fill (crop)'],['contain','Fit (no crop)']]`; §19 asks for cover / contain / **fill**, and there is no object-position / focal-point control, so an operator can't stop a logo being cropped at the wrong edge.
**Impact:** small, cosmetic, non-blocking. Listed because §19 enumerates both by name and audits must be exhaustive.
**Fix sketch:** add `ToggleField`s for `showDays/showHours/showMinutes/showSeconds` (confirm the widget reads them first); add `'fill'` to the fit options and a 9-point position picker writing `cfg.objectPosition`.
**NEW.**

### [P2] F-5 — CLOCK timezone is a free-text field while the same panel already ships a timezone selector
**Evidence:** `PropertiesPanel.tsx:2916` — `<TextField key="timezone" label="Timezone (optional)" placeholder="America/Chicago">`. Meanwhile `:4550` (HS_VARSITY) uses `<SelectField … options={US_TIMEZONE_OPTIONS}>`. §19 says "Clock: **timezone selector**". A typo silently falls back to browser-local with no error.
**Fix sketch:** swap in `US_TIMEZONE_OPTIONS` with a "Screen local" empty option; keep accepting a stored IANA string for back-compat.
**NEW.**

- **Editability-contract spot check (D):** zero boards across all 184 files have `<img>` without any image-slot attribute; zero boards have fewer than 5 `data-field` hooks; sampled density 93–271 hooks per kiosk board. No "looks editable but isn't" elements surfaced.
