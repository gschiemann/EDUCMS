# Competitive + Interaction-Design Research — Game Control Consoles (2026-06-16)

Five parallel web-grounded research agents. Source for the synthesis in `01-BLEEDING-EDGE-SYNTHESIS.md`.

## Legacy scoreboard-control consoles (the incumbent operator paradigm) — Daktronics, Nevco, OES, Colorado Time Systems, plus sport-scoring apps (GameChanger et al.), with water polo as the worked example

**Products:** Daktronics All Sport 5000 / 5100 Series control console (color-coded keys, 2x16 LCD, removable sport insert + numeric sport code, EDIT-key modal entry), Daktronics OmniSport 2000 timing console (aquatics; water polo mode stores period/shot/timeout/penalty times + scores; HOME/GST/TOL/PL LCD layout), Daktronics Show Control System / Display Studio (push-button, event-first game-presentation trigger system), Daktronics Venus Control Suite (drag-and-drop media library + playlist scheduling for LED/LCD displays), Colorado Time Systems WTTC — Water Polo Wireless Tabletop Controller (double-sided blue/white insert, RSR clock paddle, Edit Mode, alt shot reset, exclusion/brutality/red-card keys, penalty-shootout mode), Colorado Time Systems System 6 — Water Polo (keyboard controls game time, shot clocks, 3 penalty times per team, scores, horn; handheld interface), Nevco MPCW-7 (and MPCW-6) wired/wireless console controller (left/right 20-key pads, 16-char LED, YES/NO/SET grammar, swappable overlay + model code, TCS-7 handheld time switch, profiles), OES ISC9000 / ISC85X integrated scoreboard controllers (field-of-text LCD entry; HOME/VISITOR PENALTY -> jersey# -> ENTER), GameChanger scorekeeping app (event-first stat entry with auto follow-up prompts; media/stats layer, not live board control), iScore / MaxPreps scoring / Hudl Sideline scoring (sport-scoring apps), NFHS 'Working the Water Polo Desk' (the human-crew control paradigm: Scorekeeper, Exclusion Secretary, Game Timer, Shot-clock operator)

**Control paradigm:** OBJECT-FIRST, modal, field-edit. The incumbent mental model is "the console IS the scoreboard's state, mirrored." Every legacy console — CTS WTTC, Daktronics All Sport 5000 / OmniSport 2000, Nevco MPCW-7 — is a fixed membrane keypad whose physical layout mirrors the board: a HOME (left) block and a GUEST (right) block, each with +1/-1 score, plus a shared center clock block (Run/Stop, Reset, Period, Horn) and a numeric keypad. The operator's whole job is to keep the console's internal object-state (score, period, shot time, exclusions, timeouts) in sync with what just happened in the pool; the board is a dumb mirror of that state. Two interaction primitives dominate: (1) DIRECT INCREMENT — press +1 and the field steps live (no confirm); (2) MODAL EDIT — to set an exact value you press a mode key first (Daktronics EDIT, Nevco SET, CTS "Edit Mode"), then the target field key, then type digits on the numeric keypad, then ENTER; CLEAR/NO aborts and reverts. Critically, the operator is NOT thinking in 'events' ('a goal happened, log it') — they're thinking in 'fields' ('drive the SCORE field up by one'). Penalties are the one place the model bends toward events: press EXCL/penalty key → type the offending player's cap number → ENTER, and the console spawns and runs a countdown timer object it then has to manage (enable/disable, delete, clear-all, roll-up). Clock control is split off the keypad onto a dedicated hand-held Run/Stop/Reset (RSR) switch so a SECOND human can run time while the scorekeeper drives the keypad — the consoles are explicitly architected for a 2–4 person crew, not a single operator. Sport selection is itself modal: you physically swap a printed plastic 'overlay/insert' over the keys AND type a sport CODE to relabel the same hardware (the keys never move; only the legend does). Separately, the GAME-PRESENTATION layer (crowd prompts, replays, sponsor reads, video) is a totally different product and operator — Daktronics Show Control / Display Studio is EVENT-FIRST and rundown-driven (push-button triggers fire pre-built content sequences), and Venus Control Suite is a drag-and-drop media/playlist scheduler. So in the legacy world the scorekeeper and the show-caller are different people on different boxes with no shared state — exactly the seam VenueOS collapses.

**Strengths**
- Spatial muscle memory: the keypad physically mirrors the board (HOME keys left, GUEST right, clock center). An operator can drive it eyes-up on the game because the +1 is always in the same place — our biggest thing to preserve, and our current symmetric two-panel 'Full' view already honors it.
- Direct-increment with zero confirm for the 99% action: +1 score / period advance just happen. No modal, no 'are you sure'. Speed beats safety for the common case; safety lives in a separate -1/undo path.
- Hardware tactility + no-latency, no-network: membrane keys give a physical click, the box talks straight to the board over serial/RF. There is no app to crash, no Wi-Fi to drop mid-period. This is the reliability bar a phone-driven console must clear or visibly fall back to.
- Purpose-built clock ergonomics: a dedicated physical Run/Stop/Reset paddle (RSR) lets the timekeeper start/stop on the ref's whistle without looking at a screen, and lets you split clock duty to a second person. Single most-pressed control in the building gets its own dedicated hardware.
- Shot clock is correctly modeled as SLAVED to the game clock with a one-button reset (to 30, or an Alt-reset to 20 on the CTS WTTC), plus an explicit 'Recall/revert shot time' undo for the mis-reset — the single most common shot-clock error, given a first-class undo.
- Exclusion/penalty entry is genuinely event-shaped and fast: one key + cap number + ENTER auto-spawns and auto-starts the countdown; CTS even auto-clears exclusions on a goal and 'rolls up' expired ones. Deep domain logic baked in.
- Rich game-rule config that we'd never guess: per-period lengths, interval/halftime/OT lengths, warning-horn lead times, '4 volume settings x 8 horn tones', auto-advance-vs-manual at period end, 'what to show on shot clock when shot time > time left in period'. Decades of edge cases encoded.
- Profiles: Nevco/CTS let you save a named game/team profile and reload it — pre-build the matchup, not reconfigure at the table.
- The system DESIGNS FOR A CREW. NFHS 'Working the Water Polo Desk' shows the real table is 4 roles — Scorekeeper (paper, official record), Exclusion Secretary (flags + re-entry timing), Game Timer (clock on whistle), Shot-clock operator. The consoles' split RSR + separate shot-clock head reflect that reality.

**Weaknesses**
- Modal edit is a notorious foot-gun. Daktronics requires 'CLEAR/NO pressed TWICE to escape'; CTS time entry needs tenths ('1:20.0') or it mis-parses; Nevco silently zero-fills unfilled digits if you hit YES early. Every operator guide spends pages on how to NOT make an error and how to find the 'oops button' — the modal grammar is the source of most mistakes.
- 16-character, 2-line monochrome LCD is the entire feedback surface. State that matters (which exclusion is in which scoreboard 'slot' A/B/C, run/stop state of the shot clock shown only as a tiny play/pause glyph) is cramped, abbreviated, and easy to misread under pressure.
- Sport-switching = swap a physical plastic overlay AND type a numeric model/sport code. Lose the insert and the keys are unlabeled; the legend and the function can desync (wrong insert = wrong mental map).
- No real undo history. There's -1 and 'Recall shot time', but no event log you can scrub. The 'official record' is literally a PAPER scoresheet a human keeps in parallel and cross-foots every period — the console can't reconstruct 'what happened at 5:37 in Q3'. Our server-backed Run-of-Show undo rail is a categorical leap.
- Requires 2–4 trained humans. The whole NFHS desk choreography (exclusion secretary calculating re-entry times by hand — 'add 40 seconds and subtract 1 minute' — and raising colored flags) exists because the console can't. Single-operator-from-a-phone is a paradigm the incumbents structurally can't offer.
- Cross-vendor inconsistency is a known hazard: NFHS explicitly tells timers to re-check, per game, 'there are some differences between major scoreboard manufacturers' — does the shot clock blank under 30s? does ending a timeout early require a manual cancel or the game clock won't start? Tribal, per-box knowledge.
- Score-SIDE / team-color mapping is a manual chore: white-left/dark-right must match the board, and the guide warns you 'may have to re-label dark and white on the console.' A double-sided keyboard insert exists JUST to flip team sides.
- Scorekeeping and game presentation are entirely separate products/operators with NO shared state — Daktronics Show Control + Venus is a different box for crowd prompts/sponsors/replays. Sponsors and celebrations are bolted on by a second human watching the same game with zero awareness of score state.
- Setup is hostile: wireless 'Channel + PAN ID' must be hand-matched between console and board ('must match the channel displayed next to the C when the board turns on'), with documented interference flakiness once a crowd with phones arrives.
- Penalty/exclusion timers are a managed-object burden on the operator: enable/disable counting, delete one, clear-all, double-exclusion, brutality-to-slot-C, roll-up rules — all manual key-sequences the operator must remember mid-chaos.
- Scoring APPS (GameChanger, iScore) solve the data/stats side beautifully (made-shot -> auto-prompt 'who assisted?', missed -> 'who rebounded?') but DON'T drive the physical board or run a live clock/shot-clock — they're a 'media/stats layer, not the live-control layer.' Nobody connects great stat-entry UX to live board control.

**Steal for VenueOS**
- Keep the spatial HOME-left / GUEST-right symmetry as sacred. It's the one thing 40 years of operators have in muscle memory — our two-panel 'Full' view is right; never reflow it responsively in a way that swaps sides. Add the double-sided-insert trick as a one-tap 'Swap sides' to match the board's white/dark layout.
- Two-tier interaction grammar, made explicit and SAFE: tap = direct increment (no confirm) for +1/score/period; a clearly separate 'Set exact' affordance (long-press the number, or a small ✎ on each field) opens a numeric pad with live preview + explicit Cancel that REVERTS — fixing the legacy 'CLEAR twice / wrong-digit zero-fill' foot-gun. We already have ⌨ Set-time type-in; generalize that pattern to every numeric field.
- Make the shot clock a slaved object with a one-tap reset AND a first-class 'Undo shot reset' (the legacy 'Recall Shot Time'). Default 30, alt-reset 20 as a second visible button — exactly the CTS WTTC pair. Show run/stop as an unmissable state, not a 6px glyph.
- Exclusion/penalty entry should be the fast event path it is on the console: one tap on the team's panel -> cap-number entry -> auto-spawn a running 20s exclusion chip. Bake in the domain logic the console has: auto-clear-on-goal toggle, auto-start when clock runs, roll-up of expired exclusions, double-exclusion, and 'carries to next period.' This is our Penalty Box view's spec.
- AUTO-CALCULATE the exclusion re-entry time and surface it big. The NFHS desk does this by hand ('player out at 2:13 -> re-entry 1:53'). Show a live countdown chip AND the absolute re-entry game-time, with a color flash at 0 — we replace the human flag-raiser. This is a killer water-polo-specific win the incumbents leave to a person with literal flags.
- Treat the clock as the most-pressed control and give it phone-thumb primacy: a giant Stop/Start the size of the whole clock block, plus -1s/+1s nudges. Offer an optional dedicated 'clock-only' role view (?view) so a second person can be the RSR paddle on their own phone — multi-operator without multi-hardware.
- Build the Run-of-Show undo rail as the EVENT LOG the paper scoresheet has always been but the console never had: named, scrubbable, server-backed, per-period totals that auto-foot. This makes our box simultaneously the controller AND the official record — something no incumbent does.
- Ship pre-game PROFILES / matchup setup (rosters, cap numbers, period/OT lengths, sponsor rotation) so game night is zero-config — the Nevco/CTS profile idea, but cloud-synced and shareable. Pair with the Hand-off QR so a volunteer can be handed a ready-to-run console.
- Encode the deep rule-config the incumbents have so we're not naive: per-period/interval/OT lengths, warning-horn lead times, auto-advance-vs-hold at period end, horn tone/volume, shot-clock-vs-game-clock display rule under 30s. Put these in Presentation/Game Settings, not in the operator's face mid-game.
- Collapse the scorekeeper/show-caller seam the legacy world keeps separate: because OUR console owns the score state AND the screens, a goal can auto-fire the celebration deck + horn + ribbon cue with zero second-operator — the exact integration Daktronics splits across All Sport (score) and Show Control (presentation). This is the whole VenueOS thesis; make it the demo.
- Per-game manufacturer-quirk reminders are tribal in the legacy world — turn that into a pre-game CHECKLIST card (sides correct? shot clock blanks <30s? horn tones differ? timeout-cancel behavior?) drawn straight from the NFHS timer checklist, surfaced in Setup.
- Steal GameChanger's follow-up-prompt pattern for stats WITHOUT slowing live control: after a goal, an OPTIONAL, dismissible 'who scored? (cap #)' chip that enriches the event log/stats but never blocks the next tap. Best of the app world fused with live board control — which neither side does today.

**Bleeding-edge ideas**
- Single-operator-from-a-phone that REPLACES the 4-person NFHS desk. Auto re-entry-time calculation, auto-exclusion-clear-on-goal, and a digital flag (color-flash on the ribbon when a player may re-enter) eliminate the Exclusion Secretary, the flags, and the mental arithmetic. No incumbent can do this because their box can't compute or display it — they delegate it to humans.
- Console = controller AND official record in one. Server-backed, immutable, scrubbable event log auto-foots per-period totals and exports the official scoresheet (PDF) at game end — collapsing the parallel paper-scoresheet ritual the NFHS desk still runs alongside every console.
- Score-state-aware automatic presentation: a goal delta auto-fires celebration + horn + ribbon + sponsor-impression logging because the same brain owns score and screens. Legacy = Daktronics All Sport (score) and Show Control (show) are different boxes/people; we make the goal itself the trigger.
- Multi-operator without multi-hardware: hand-off QR spins up role-scoped phone views (clock-only paddle, PA, show-caller, penalty box) that all bind to ONE shared live game state. The legacy RSR-paddle/2-operator model, but every paddle is just someone's phone and they all see the same truth.
- Zero-config game night via cloud profiles + opponent import: pre-stage rosters/cap numbers, period/OT structure, and sponsor rundown before you arrive; the only thing left at the table is Start. Beats the local-only Nevco/CTS profile by being shareable and handed to a volunteer.
- Modal-edit foot-gun, eliminated by design: every exact-value entry is non-destructive with live preview and a revert-on-cancel, so the canonical 'CLEAR twice to escape' / 'wrong-digit zero-fill' errors that fill incumbent manuals simply cannot occur.
- Optional stats-on-the-side a la GameChanger fused with live control: dismissible post-event chips ('who assisted?') build box-score + shot charts from the SAME taps that drive the board — uniting the stats-app world and the board-control world that have never been the same product.
- Cross-vendor pre-game checklist as software: encode the NFHS 'differences between manufacturers' gotchas (sides, shot-clock-blank-under-30s, timeout-cancel-or-clock-won't-start, distinct horn tones) into a guided pre-flight so a volunteer is as safe as a 20-year veteran timer.
- Resilience that out-flanks the 'a phone will fail mid-period' objection: local-first state with an offline queue + a visible health pill per surface (board/ribbon/stream), and an optional hardware Run/Stop paddle (BLE) that maps to our clock — keep the tactile clock control operators trust while everything else is software.
- Color/side auto-mapping from team brand kits: the console reads each team's cap/brand color and auto-places white-left/dark-right to match the board, killing the manual 're-label dark and white on the console' chore and the double-sided physical insert entirely.

## Broadcast graphics & live production control — rundown/automation systems (Ross XPression + OverDrive/Cuez, Vizrt + Viz Mosart, Singular.live, vMix, esports observer HUDs, newsroom rundowns) vs. HS/college venue scoreboard control

**Products:** Ross XPression (+ XPression Sequencer / Remote Sequencer, Take IDs, Tessera multi-screen), Ross OverDrive (APC) + CX-3E shot-box panel, QuickCode/QuickRecall/V-keys, Ross Cuez Automator (cue-blocks in MOS rundowns, one-person shows), Vizrt Viz Mosart (Rundown View, Showmaker web, AV Automation templates) + Viz Pilot Edge / Viz Flowics, Singular.live (Control Apps: Studio & unos; Logic Layers; In/Out animation states), vMix (overlay channels, transitions, keyboard/MIDI/Stream Deck shortcuts, web second-operator, score-delta scoreboards), OBS + browser-source scoreboard overlays (Daktronics via NewTek DataLink, Sportzcast, Stat Crew), LHM.gg esports observer/HUD + Scout-AI / Replays auto-cinematics; MyHUD, Newsroom rundown systems: ENPS, Avid iNews (MOS/NRCS), Rundown Creator, Daktronics All Sport 5000 console (the venue-scoreboard incumbent — sport-code keypad, score-entry only)

**Control paradigm:** RUNDOWN-FIRST, not object-first. The spine of every pro broadcast tool is an ordered, time-aware list of segments/graphics (the "rundown" / "episode" / "sequencer"). The operator's loop is ARM (cue the next item, prep it off-air) → PREVIEW (it's staged but not live) → TAKE (one button puts it on Program). Two hard states everywhere: NOW (on-air, marked RED) and NEXT (armed, marked YELLOW) — Viz Mosart literally color-codes the rundown that way, and the whole show advances by repeatedly "taking the next item." Crucially the unit of action is "advance the show," not "edit this widget": a director/show-caller drives the spine while specialized operators (graphics, replay, audio) own their lanes, coordinated verbally over intercom with a rigid STANDBY → GO call-and-response. Automation systems (OverDrive, Cuez, XPression sequencer) collapse that multi-person choreography into one button — "QuickCode"/cue-blocks fire many devices at once so one person can run the show. Singular.live adds the orthogonal axis: graphics live on LOGIC LAYERS where putting one element "In" auto-pulls the conflicting element "Out," so the operator can never leave two mutually-exclusive overlays on screen at once. vMix's everyday reality is hotkeys/Stream Deck + score-deltas (+=2/-=1) + a second web operator on a phone. By contrast the HS/college scoreboard console (Daktronics All Sport 5000) is pure object-first score-entry: a sport-code keypad that sets clock/score fields with zero notion of a rundown, a NEXT item, preview-vs-program, or a presentation sequence.

**Strengths**
- Rundown as the single source of truth: an ordered, timed list (Mosart rundown, Cuez episode, XPression sequencer) means the operator always knows what's NOW and what's NEXT — the show advances itself, the operator just confirms.
- Hard NOW/NEXT visual grammar: Viz Mosart marks on-air RED and next-to-air YELLOW directly on the rundown; color-codes every element type (camera=green, graphic=yellow, live=red, DVE=yellow+red) so a glance reads the whole show state.
- Arm-then-take safety: graphics are staged in PREVIEW and prepped off-air, then committed with one deliberate TAKE — you never edit live by accident, and a single Take ID can fire one engine or dozens in perfect sync (XPression).
- Take-out discipline: Mosart's AUTOOUT / BACKGROUNDEND / STORYEND / OPENEND modes encode WHEN each graphic leaves screen, so overlays don't get orphaned — removal is as designed-for as insertion.
- Mutual-exclusion by construction: Singular Logic Layers guarantee two conflicting overlays can never both be 'In' — sending one in auto-animates the other out, eliminating a whole class of operator error.
- One-button multi-device orchestration: OverDrive QuickCode / Cuez cue-blocks fire switcher+graphics+audio+robotics together, letting one person run what used to need a full gallery ('touched the switcher 5 times in 8 years').
- Graceful manual↔auto spectrum: the same console runs full-auto, assisted (V-keys/templates), or fully manual at any moment — the operator can always grab the wheel mid-show without leaving the tool.
- Hardware-surface reality: vMix/OverDrive assume a Stream Deck / MIDI / shot-box with hotkeys and score-deltas (+=2, -=1); the fast path is physical buttons, not on-screen taps.
- Distributed multi-operator + multi-location: esports LHM and Mosart let graphics op, producer, and observer work from different machines/locations against one cloud rundown without breaking the show.
- Disciplined human coordination protocol: the STANDBY→GO intercom etiquette (silence on standby, crisp single-word GO) is a battle-tested model for one caller directing several operators in real time.

**Weaknesses**
- Brutal learning curve: XPression/Mosart/OverDrive assume a trained broadcast operator and a control room — wrong target for a volunteer parent or a coach running it from a phone at a Tuesday water-polo match.
- Heavy infrastructure & cost: these are control-room systems (panels, MOS/NRCS integration, 275+ device drivers in OverDrive) — massively over-built for a single LED ribbon + scoreboard at a high school.
- Rundown authoring is a job: building the Mosart/Cuez rundown ahead of time is itself skilled labor; there's no 'the app pre-built your show' on-ramp for a non-broadcast operator.
- Two-surface mental model (Preview vs Program) is powerful but confuses novices — people put the wrong thing 'on air' constantly until trained; it needs heavy UX scaffolding to be safe for amateurs.
- Sport-specific scoring is an afterthought: broadcast tools treat the scorebug as just-another-graphic; they have no native notion of shot-clock vs game-clock slaving, exclusions/penalty box, sprint cap, or auto-reset-on-period — exactly the stuff a venue scoreboard must get right.
- Daktronics-class venue consoles are the opposite failure: rock-solid scoring, but ZERO presentation layer — no rundown, no NEXT, no preview, no celebration sequencing, no sponsor rotation, no multi-surface targeting. The score is entered and that's the end of the product.
- Verbal coordination doesn't scale to one person: the STANDBY/GO protocol assumes multiple humans on headsets; a solo phone operator gets none of that structure unless the app encodes it.
- Logic-layer / take-out semantics are invisible to the user — powerful but opaque; if the venue product copies the behavior it must also surface WHY something left the screen.

**Steal for VenueOS**
- Add a NEXT/NOW spine to the console. Today's mockup is pure object-first (symmetric team panels = direct-manipulation scoreboard). Layer a thin RUNDOWN rail on top: an ordered, timed list of presentation beats (pre-game lineup → national anthem → tip/sprint → sponsor read → halftime → senior-night recognition → celebration cues). Mark the current beat NOW (red) and the staged one NEXT (yellow), exactly like Viz Mosart. The existing bottom 'Run of Show' undo rail is the seed — promote it from a backward-looking undo log to a bidirectional spine that also shows what's COMING and lets you arm+take it.
- ARM → TAKE for anything that hits the LED/board/stream that isn't a live score tick. Score +1 stays instant (object-first is correct for scoring). But celebrations, sponsor reads, text overlays, lineup graphics, halftime content should be ARM-in-preview then TAKE-to-air with one big confirmed button — borrow XPression's single Take ID firing board+ribbon+stream in sync. This directly upgrades the current 'celebrate row + All/Board/Ribbon target selector' into a previewable, committed action instead of a fire-blind tap.
- Adopt Singular Logic Layers as a hard invariant on the send targets. Exclusions, Power Play, Timeout, and Review-overlay are mutually exclusive game-states — encode them as one logic layer so triggering Power Play auto-clears Exclusion on every surface. Eliminates the 'two contradictory overlays stuck on the ribbon' failure class by construction, not by operator vigilance.
- Encode take-out modes (Mosart's AUTOOUT/STORYEND/OPENEND) per cue. A water-polo exclusion overlay should auto-clear at end-of-exclusion (clock-driven AUTOOUT); a sponsor read auto-clears after N seconds; a manual text overlay stays until dismissed (OPENEND). Bake the removal rule into the cue so overlays never orphan on the ribbon.
- Ship a Stream Deck / hotkey / MIDI control map like vMix + a second-operator web view. The Show-Caller view should be drivable from a physical deck for the power operator, and the Hand-off QR should spin up a scoped second operator (e.g. a kid runs the score on a phone while the AD runs the show) — vMix's 'second operator from any web device' + score-deltas (+=2/-=1) is exactly the multi-person model the QR hand-off is reaching for.
- Make the Show-Caller view a real directing surface, not just a tab. Model the STANDBY→GO protocol in software: the caller arms a beat (broadcasts a soft 'standby' to the scorekeeper/PA views), then a single GO commits it across surfaces. Turns the 13 role-views from independent panels into a coordinated multi-person show with one person in charge — which is the whole point of a show-caller.
- Pre-build the rundown per sport so authoring isn't a job. Cuez/Mosart make you build the show; VenueOS should ship a water-polo rundown template (lineups → sprint → quarter cues → exclusions logic → timeouts → celebration deck → final) auto-seeded the moment you pick the sport, so a coach gets a working show on first open — the Integration-Concierge 'app almost does the work for them' ethos applied to game presentation.

**Bleeding-edge ideas**
- AUTO-RUNDOWN from the score feed: the CTS/Daktronics bridge already knows clock, period, shots, exclusions. Use it to AUTO-ARM the next beat — clock hits 0:00 in Q4 → 'Final / celebration deck' goes to NEXT (yellow) automatically; an exclusion is entered → the penalty-box overlay arms itself. The operator just confirms TAKE. No broadcast tool ties the rundown spine to the live game-state feed like this because they're sport-agnostic — VenueOS can, because it owns both the scoreboard and the show. This is the genuinely novel wedge.
- Score-driven logic layers: marry Singular's mutual-exclusion to live water-polo state so game-state transitions (even strength → power play → penalty shot) drive which overlay is 'In' on every surface automatically, with the operator able to veto. Self-correcting presentation.
- One-button 'GO' that the AUTO system can pre-stage AND a human can override — a hybrid of OverDrive's manual/assisted/auto spectrum but with the auto-suggestions coming from the actual game feed, not a pre-timed news rundown. 'The show calls itself, you confirm.'
- Phone-as-Stream-Deck for the volunteer: the Hand-off QR spins up a second device showing only 4-6 huge ARM/TAKE beat buttons (the NEXT beats the show-caller staged) — turning any parent's phone into a scoped, idiot-proof Stream Deck. Pro hotkey ergonomics without pro hardware.
- Make take-out modes visible and reassuring: a tiny countdown badge on each live overlay ('Power Play overlay — auto-clears at 0:00') so an amateur operator trusts the system to remove things, the single biggest thing that scares novices off preview/program workflows.
- Replay/celebration auto-capture like LHM Scout-AI but for HS: when a goal-delta fires, auto-stage (NEXT, not auto-air) a celebration deck pre-loaded with the scorer's cap-number graphic pulled from the roster chips — operator just hits TAKE. Bridges esports auto-cinematics into a $0-budget high-school gym.

## Modern venue display + HS/college game-presentation challengers (ScoreVision, BlueFrame/Hudl TV, Pixellot, NFHS Network/PlayOn) + pro real-time stat-entry systems (Genius Sports FIBA LiveStats, Daktronics DakStats, StatBroadcast StatInput, Sportradar, Synergy Sports)

**Products:** ScoreVision (Scorekeeper App, Producer App, Capture App, Cloud), BlueFrame Technology / Hudl TV (Production Truck, vCloud), Pixellot (AI auto-production cameras + Auto Graphics), NFHS Network / PlayOn! Sports (PlayOn Producer, Pixellot integration), Genius Sports — FIBA LiveStats v7 (Predictive Workflows), Daktronics DakStats (Two-Click Mode, Keystroke Entry, Suggested Plays), StatBroadcast — StatInput (touch/mouse/keyboard tri-modal), Sportradar (live data collection scout app), Synergy Sports (live possession tagging)

**Control paradigm:** Two competing paradigms, and the leaders deliberately keep them on SEPARATE devices. (1) EVENT-FIRST stat entry: a trained scorer records "what happened" (shot location, player number, made/missed) and the score/clock/graphics are DERIVED side effects — this is the pro/stat world (DakStats, FIBA LiveStats, StatInput, Sportradar). Entry is optimized to 2 inputs per event via "predictive workflows" / "suggested plays" that pre-arm the next likely action, OR via single-key shorthand ("type the play"). (2) SHOW-FIRST production: a separate operator drives layouts, animations, replays and sponsor reads on the board (ScoreVision Producer, BlueFrame Production Truck, PlayOn Producer). ScoreVision's explicit guidance is to run Scorekeeper and Producer on TWO different iPads with two people — scoring must never block the show, and the show must never corrupt the score. The bridge between the two is auto-graphics: assigning a point in the scorekeeper lights up a "one-touch Player Accolade" that fires a named animation on the board. Our console collapses both roles into one symmetric object-first surface, which is fine for a one-person HS water-polo table but loses the leaders' "scoring is fast and dumb, the show is a separate brain" discipline.

**Strengths**
- DakStats 'Suggested Plays' / FIBA LiveStats 'Predictive Workflows': after you enter a made shot the system AUTO-ARMS the next likely action (assist-by, fast-break, rebounder) as highlighted buttons you can confirm or ignore — collapsing a multi-stat play to ~2 taps and removing the 'what do I press next' hesitation.
- DakStats keyboard 'Keystroke Entry' = true type-the-play shorthand: one letter for the action (J=jumper, D=dunk, L=layup, Y=3pt; E=FT, R=rebound, A=assist, F=foul, T=turnover, S=steal, K=block, O=timeout), then player number, then a result key (G/Q=good, R=missed→rebound, X=missed-3). H/V switch the active team; Space starts/stops the clock. A trained scorer never leaves the keyboard.
- Spatial = semantic: in DakStats and FIBA LiveStats you click a COURT, not a number field — left-click=missed, right-click=made, and behind-the-arc location AUTO-DETECTS a 3-pointer and auto-tags paint/2nd-chance. Position carries data, so fewer explicit fields.
- ScoreVision's hard role split (Scorekeeper iPad + Producer iPad, recommended as separate devices/people) keeps fast, error-prone scoring isolated from the high-stakes show controls; the Producer app is a true 'universal remote' (power, brightness, audio, camera feed, layout toggle: full-scoreboard / video+scoreboard / leaderboard / full-video).
- Auto-graphics as the payoff: ScoreVision lights a 'Player Accolade' button the instant you credit a player, one tap fires a named hype animation ('Slam Dunk', 'Touchdown') with that player's profile — the celebration is a one-tap consequence of scoring, not a separate hunt-for-the-button. Pixellot/NFHS push this further: score+clock are read off a scoreboard tap-in box and auto-overlaid with NO operator at all.
- Cloud-prepped game context: rosters, seasons, schedule and the sport's RULES are loaded into the cloud account before the game so the in-game UI shows real names/cap numbers and can enforce/auto-calc (ScoreVision football auto-computes down & distance from ball drag; 3pt auto-detect in DakStats).
- StatBroadcast StatInput is explicitly tri-modal — the SAME web app accepts touch, mouse, OR keyboard entry, browser-based, zero install, and supports a SECOND device auditing/correcting plays live while the primary scorer keeps going.
- Durable correction model: every system treats the event log as the source of truth with a visible play-by-play script you can edit/insert/delete/move + 'Delete Last Play' + 'Rebuild Stats' — totals are recomputed from the event stream, not hand-patched.

**Weaknesses**
- DakStats is a Windows-desktop app (1024x768, mouse + full keyboard) — fast for a trained statistician at a press table, hostile on a phone/tablet at a pool deck; no touch-target discipline, dated chrome.
- The pro stat tools (DakStats, FIBA LiveStats, StatInput, Synergy, Sportradar) assume a TRAINED, CERTIFIED operator — the keystroke shorthand and predictive prompts have a real learning curve and zero affordance for a volunteer parent running their first water-polo game.
- Role split has a cost: ScoreVision needs TWO iPads and TWO trained people to get scoring + show simultaneously; a single small-venue operator can't do both well at once.
- Fully-automated systems (Pixellot/NFHS) win by removing the operator — but they also remove operator EXPRESSION: the graphics are templated overlays, you don't get bespoke per-moment show-calling, sponsor reads, or a custom celebration deck.
- Stat-first systems are built for a stats audience (box scores, NCAA XML, lineup-efficiency reports), not for driving an in-venue LED show — the in-venue scoreboard is an afterthought output, so celebration/ribbon/sponsor presentation is thin or absent.
- Heavy cloud/season pre-load dependency: if rosters/schedule aren't prepped in the cloud, the streamlined name-driven entry degrades to generic number entry; not great for pickup games or last-minute roster changes.
- Synergy/Sportradar live collection is a back-office logging pipeline (loggers tagging possessions for analytics/betting feeds), not an operator-facing venue control surface — relevant for shorthand inspiration, not for show control.
- Per-sport apps fragment the experience (ScoreVision ships separate Basketball/Soccer/Wrestling/Universal apps) instead of one design system across sports — the opposite of our 13-view/one-system goal, and a maintenance + muscle-memory tax.

**Steal for VenueOS**
- Add a PREDICTIVE 'next-action' layer on top of our +1 buttons: after a GOAL, auto-arm the likely follow-ups as highlighted, dismissable chips — 'Assist by #__', 'Exclusion drawn', 'Sprint won' — so a multi-part water-polo play is 2 taps, and the operator never wonders what to press next. This is DakStats 'Suggested Plays' / FIBA 'Predictive Workflows' and it's the single biggest speed unlock.
- Ship a real type-the-play KEYBOARD shorthand for the Mac/iPad-with-keyboard scorer, mirroring DakStats keystroke entry: G=Goal, S=Save, E=Exclusion, P=Power-play, then digit(s)=cap number; H/A pre-select team; Space=start/stop clock; one key = one event on the Run-of-Show rail. We already have keyboard shortcuts (T2-2) — formalize them into a documented, on-screen 'shorthand cheat row' the way DakStats prints its key table.
- Make POSITION carry data where it helps water polo: a tap on a mini pool diagram could set the shot/exclusion side, or at minimum let a single gesture distinguish made-vs-missed (DakStats left-click=miss / right-click=made). Keep it optional — power feature, not a gate.
- Tighten the score->celebration coupling like ScoreVision's one-touch Player Accolade: the moment a +1 is credited to a cap number, surface a single glowing 'Celebrate #7' button pre-bound to that player's name/photo and the GOAL deck — don't make the operator re-pick the player in the celebrate row.
- Adopt the explicit ROLE-SPLIT-AS-VIEWS pattern but keep it one device: our top-bar Scorekeeper / Show-Caller / PA / Cues views already mirror ScoreVision's two-iPad division — lean into it. Let a venue OPTIONALLY hand the Show-Caller view to a second device via the Hand-off QR (we have the QR) so a big venue gets two operators, a small one gets one, same design system. That beats ScoreVision's fixed two-app requirement.
- Treat the Run-of-Show rail as the canonical EVENT LOG with edit/insert/delete/move + 'Rebuild from events' (DakStats Play-by-Play Script + Rebuild Stats), so all derived state (score, shots, board, stat feed) recomputes from the log — we already have a server-backed undo rail (T1-2); expose the richer edit operations.
- Pre-load the game like the leaders: rosters + cap numbers + sport rules loaded before tip so the console shows real names and AUTO-CALCS what it can (shot clock 30/20 logic, exclusion 20s countdown, sprint) — reduce manual fields the same way ScoreVision auto-computes down & distance and DakStats auto-detects a 3.
- Offer a tri-modal entry promise like StatInput (touch / mouse / keyboard, same web surface, zero install) and advertise it — our phone/iPad/Mac story is already this; name it and prove a second device can audit/correct live while the primary keeps scoring.
- Optionally INGEST a scoreboard/console tap-in (Pixellot/NFHS model + our CTS/Daktronics parser work) so score+clock can be AUTO-derived and the operator is freed to only call the show — graceful auto-mode for venues that have a console, manual mode for those that don't.

**Bleeding-edge ideas**
- One-person 'auto-pilot + override' mode: ingest the existing scoreboard/console feed (we have CTS/Daktronics parsing) so score, clock, shot-clock and exclusions auto-update like Pixellot/NFHS — then the lone operator does NOTHING but call celebrations and sponsor reads. Nobody in HS/college gives you full automation AND bespoke show-calling on the same board; the leaders make you pick.
- Predictive shorthand that LEARNS the sport's grammar: after GOAL, the console knows water polo restarts at center, the shot clock resets, and an exclusion likely cleared — pre-stage all of it as one-tap confirmations. Push it to a voice/keyboard 'call the play in plain language' ('goal seven, assist three') that parses to events — beyond DakStats' single-key codes.
- A built-in, on-screen SHORTHAND CHEAT ROW that doubles as the buttons: the same row teaches the keys AND is tappable, so a volunteer uses taps and graduates to keys in the same UI — collapsing the trained-operator learning curve that gates every pro stat tool.
- Score-change -> auto-celebration with PLAYER IDENTITY baked in by default (cap number -> name + photo -> named deck) firing in <1s, the ScoreVision accolade idea but automatic on the AUTO trigger we're already building (#45) — make the celebration the default consequence of a goal, with a tap to suppress, not a tap to fire.
- Sponsor-aware auto-show: tie celebration/ribbon cadence to a frequency-capped sponsor rotation (we have T2-9 impression logging) so every auto-fired GOAL animation can carry a 'brought to you by' lower-third — turning the stat event into logged, billable sponsor impressions. Stat tools generate XML; nobody monetizes the celebration moment.
- Cross-device role hand-off via QR as a first-class feature: scan to instantly promote a phone into a dedicated PA or Show-Caller surface mid-game, with the design system intact — ScoreVision needs pre-provisioned second iPads + training/approval; we make the second seat a 5-second scan.
- Event-sourced, fully reversible game state where the Run-of-Show rail is the database: any board, ribbon, scorebug-overlay, or stat-feed output is a pure projection of the event log, so 'undo' is bulletproof across every surface at once — the durable-undo + typed-GameState work (T1-2, T3-1) taken to its logical, demo-able end.

## Hardware control surfaces &amp; eyes-up / do-what-no-one-does control paradigms (Stream Deck/Companion, MIDI/foot pedals, command palettes, Ableton/Push performance grids, cockpit HMI, replay/lighting consoles, Apple Watch glance, POS verb-first, predictive UI) — applied to a live water-polo game-control console.

**Products:** Elgato Stream Deck (+ Pages/Folders/Multi-Actions, Stream Deck Pedal foot switch), Bitfocus Companion (button feedback, variables, triggers, conditional actions, surfaces/web-buttons), Command palettes: Superhuman, Linear, Figma, Raycast, VS Code, Slack (Cmd-K), Ableton Live Session View + Push 2/3 (clip-launch grid, scenes, follow actions, color pads), MIDI foot controllers: Looptimus/Looptimus+, Morningstar MC-series, Nektar PACER, Singular MIDI Maestro, EVS LSM-VIA + XT-VIA / Datavideo HDR-10A (jog/T-bar/shortcut replay controllers), ETC Eos family lighting consoles (Load/GO armed-cue playback), Apple Watch complications / watchOS glanceable design, Avionics Primary Flight Display / cockpit HMI, Touchscreen QSR POS (verb-first drill-down: item→modifier→combo), Broadcast tally lights / vMix-style Program/Preview state

**Control paradigm:** Event-first + armed-cue, NOT object-first. The strongest live-control surfaces outside sports almost never make the operator (a) navigate to an object, then (b) edit a property. Instead they expose a flat field of pre-labeled, pre-loaded VERBS the operator fires by reflex — Stream Deck/Companion keys, Ableton clip pads, ETC Eos GO/Load, a foot pedal — with the system carrying the state. Three reinforcing ideas run through every reference: (1) PRE-AUTHOR THEN FIRE — the thinking happens before the event (program the deck, build the cue stack, lay out clips); during the event you only trigger. (2) THE SURFACE REPORTS BACK — every key/pad shows live state (Companion feedback, Push pad color, tally red/green/grey), so the operator confirms by glance, never by reading. (3) HANDS AND EYES STAY ON THE GAME — foot pedals, jog wheels, muscle-memory key positions and 1-second-glance complications exist specifically so the operator never looks down. Our current mockup is object-first-leaning (two symmetric team panels you read and adjust); the bleeding-edge move is to keep that as the "scorekeeper" detail view but make the DEFAULT live surface a fixed, labeled, color-feedback verb grid + command palette + (optionally) a foot pedal for the clock — an event-first cockpit, not a form.

**Strengths**
- Stream Deck + Bitfocus Companion: a flat grid of physically-labeled keys that each fire one or a STACKED/SEQUENTIAL multi-action with one tap — the canonical 'pre-author, then fire' model. Companion adds state-driven button FEEDBACK (color/text/icon change with real device state), VARIABLES that flow between buttons, and TRIGGERS that fire actions on time/variable-change/press. Free, open-source, OSC/TCP/UDP/HTTP/WebSocket/ArtNet ingress. (bitfocus.io/companion, deepwiki Feedbacks-and-Triggers)
- Stream Deck PAGES + FOLDERS: a tiny key count scales to a whole show by switching layouts like browser tabs (10 pages/profile) or nesting folders — directly maps to per-period / per-sport / per-mode key sets. (help.elgato.com Pages, Using Folders)

MIDI foot controllers (Looptimus, Morningstar, Nektar PACER, Singular MIDI Maestro) prove the rugged stage-grade hands-free pattern: tap a switch to advance/loop/trigger without stopping. (elgato.com Stream Deck Pedal; morningstar.io; loopcommunity.com)

**Weaknesses**
- Hardware-first surfaces (Stream Deck, Push, EVS panels, MIDI pedals) require physical kit the operator must own, transport, and configure — antithetical to our 'drive it from a phone, zero IT' wedge. The pattern to steal is the INTERACTION (labeled verb grid, armed cue, color feedback), not the dependency on a $200 box.
- Companion/Stream Deck programming is a power-user setup task (button designer, variables, triggers, OSC mapping). Untranslated, it's exactly the 'need an IT consultant' pain our Concierge exists to kill. We must ship the grid PRE-BUILT per sport, not hand the operator an empty deck.
- Command palettes assume a keyboard and a literate, typing operator — weak on a phone in a loud pool deck with wet hands. On touch/mobile it must degrade to big-target verb tiles + voice, and the palette becomes the iPad/Mac power-path, not the only path.
- Ableton FOLLOW ACTIONS / scene auto-advance are powerful but can fire the WRONG thing if the show state drifts — dangerous for a live celebration that interrupts play. Auto-advance needs a hard 'this is what's armed next' preview and an instant kill, or it becomes an accident generator.
- Avionics-grade redundancy and certification rigor are overkill and slow for a HS water-polo console; we want the GLANCEABILITY and error-resistance principles, not the process weight.
- Predictive 'next best action' is only as good as its model; a wrong prediction at a high-stakes moment (suggesting GOAL Home when it was Away) erodes trust fast. Predictions must be SUGGESTIONS that pre-position a key, never auto-fires, and must be trivially overridable.
- Apple Watch's 1.2s-glance discipline is great for STATUS but its tiny canvas can't hold a 13-view design system — it's an input/confirm satellite (arm score, fire horn, all-clear), not the primary console.
- Replay/lighting tactile controls rely on the operator having trained muscle memory; a first-time HS volunteer has none. Our verb grid must be self-labeling and forgiving (undo rail, hold-to-confirm) because the operator turns over every season.

**Steal for VenueOS**
- DEFAULT 'Run' surface = a Companion-style LABELED VERB GRID, not symmetric team forms. A fixed grid of large, color-feedback keys (HOME +1 / AWAY +1 / SHOT-CLOCK 30 / EXCLUSION HOME / TIMEOUT / HORN / GOAL CEL / SAVE / POWER PLAY) that each fire a STACKED multi-action (e.g. GOAL = score+1 → horn → ribbon celebration → run-of-show log). Keep the two-panel scorekeeper view as the 'detail/correct' mode behind a tab. (Stream Deck multi-actions; Companion feedbacks)
- STATE-DRIVEN BUTTON FEEDBACK on every key — borrow tally color language: a key glows when its state is active (EXCLUSION key shows a live :20 countdown + red while a player is out; POWER PLAY pulses; HORN greys out for its cooldown). The operator confirms by glance, never by reading the board. (Companion feedback; Push pad colors; Tally light Red/Green/Grey)
- ARMED-CUE / LOAD→GO for anything irreversible on the public board. Big celebrations and emergency-ish overrides get an ETC-Eos pattern: tap arms + previews 'NEXT: GOAL CEL — Home #7', a persistent strip shows what's armed, second tap (or a confirmed swipe / pedal) FIRES. Marries safety with one-glance certainty. (ETC Eos Load/GO)
- COMMAND PALETTE for the iPad/Mac power operator (Cmd-K / long-press): fuzzy, alias-aware, context-ranked verbs — 'gh' → 'Goal Home', 'exc' → 'Exclusion…', 'cel' → celebration deck. Show the keyboard shortcut inline to TEACH it, recency-boost the operator's last actions, dismiss-on-repeat. This is our 'type the action, never look down' path. (Superhuman command palette)
- SCENES = one-tap GAME-STATE changes. Borrow Ableton scene launch: 'Pre-game', 'Sprint', 'Quarter Break', 'Timeout', 'Exclusion (man-up)', 'Final' each fire a coordinated set across scoreboard + ribbon + stream overlay in one tap. The run-of-show rail already exists; add a forward-facing SCENE row, not just a backward undo rail. (Ableton scenes / scene launch)
- PAGES/FOLDERS to scale the grid: one verb-grid layout per PERIOD/MODE and per SPORT, switched like Stream Deck pages — so water polo, basketball, hockey each get the right keys without a cluttered universal panel. Our top command bar (Scorekeeper/Show-Caller/PA/Cues…) is already page-like; make each page a purpose-built grid. (Stream Deck Pages/Folders)
- GLANCE + ONE-TAP discipline from Apple Watch on the highest-frequency keys: the +1 and clock controls must be readable/firable in ~1s without precision aiming — oversized, fixed-position (muscle memory), high-contrast broadcast type. Tested for 1-second recognition. (Apple Watch complications)

Assume operator error; design the recovery in. (avionics HMI)
- SHOW THE SURFACE ON BOTH SIDES: like Push mirroring Live, keep the phone/iPad grid and the board in lockstep — the console shows EXACTLY what the public board/ribbon is showing right now (a small live mirror), so the operator never wonders 'did it take?'. (Push ↔ Live mirroring)

## Real-time control interaction design for high-pressure, public-facing surfaces (live sports game-control console)

**Products:** 

**Control paradigm:** Two dominant paradigms exist and the right console blends them. (1) OBJECT-FIRST / direct-manipulation: each team owns a fixed, persistent panel and you act directly on it (tap Home's "+1"). This is what tablet scorekeepers like ScoreVision and the iOS water-polo apps do — home/away are spatially pinned and you manipulate the team you're looking at. Its strength is glanceability and no mode; its risk is the symmetric-mirror mode error ("which side am I on?") when the two panels look identical. (2) EVENT-FIRST / verb-then-noun: you press an action (GOAL, EXCLUSION) and then disambiguate the team — closer to a broadcast graphics rundown or QLab cue list. vMix actually splits the difference: scores are bound to dedicated +=N keyboard shortcuts (each key IS a team+delta, so there is no mode at all). The bleeding-edge answer for VenueOS: keep the OBJECT-FIRST symmetric layout for glanceability, but make every committed action self-label with the team+jersey ("GOAL Dodgers #7") the way a Run-of-Show rail does, so the operator never has to hold "which team" in working memory — the system speaks the noun back. Critically: there is NO global "edit team A vs team B" mode anywhere — symmetric panels must each carry their own always-visible identity (color, name, logo, side) so the layout is modeless by construction, per Norman/Buxton's rule that if modes exist the system must make the active one obvious.

**Strengths**
- Object-first symmetric panels (ScoreVision, water-polo tablet apps) are maximally glanceable — the operator's eyes map 1:1 to the physical pool/court, home-left/away-right, no translation step
- vMix's keyboard-bound scoring (+=2, +=3, -=1) collapses team+delta into a single dedicated key — zero mode, instant, and a second operator can drive it from any web device
- QLab's double-GO protection (configurable minimum time between GOs, red border shows it's armed) is a proven, low-friction guard against the #1 live-control error: the accidental double-fire
- Daktronics All Sport Pro's sport-profile model auto-configures scoring/timing rules per sport so the operator picks a profile and the console reshapes itself — no manual per-sport setup under pressure
- Stream Deck + Bitfocus Companion proves operators love big, color-coded, labeled, single-purpose buttons with per-button state feedback, and PIN/section locking to prevent the wrong person hitting the wrong thing
- Aviation guarded switches show the gold standard for irreversible actions: a physical two-action forcing function (lift guard, then press) plus color-coding (red = irreversible) that the whole industry has standardized on
- Broadcast tools (Ross XPression) obsess over zero perceived lag between input and on-air change — the entire category treats <100ms feedback as table stakes

**Weaknesses**
- Symmetric mirror layouts are a textbook mode-error trap: when Home and Away panels are visually identical, the operator commits to the wrong side — and on a public scoreboard the error is instant and humiliating. Most consumer scorekeeper apps under-invest here
- Confirmation-dialog overuse causes habituation — NN/G is explicit: 'if you cry wolf too many times people stop paying attention,' so a console that confirms every score change trains the operator to blind-tap 'Yes,' destroying the safeguard exactly when it matters
- Many sports apps bury clock/shot-clock editing behind swipes and small fields ('swipe the scoreboard left/right to display the shot clock') — gesture-hidden controls fail under stress and one-handed operation
- Tiny touch targets + un-debounced taps cause the classic 'fast taps register twice' double-increment; consumer apps frequently ship this
- Pure event-first (verb-then-noun) flows add a disambiguation step that costs time and creates a NEW mode ('I pressed GOAL, now which team?') — slower and more error-prone than direct manipulation for the high-frequency score case
- No examined consumer scorekeeper offers a true multi-level, named, instant undo timeline — they offer 'edit events' buried in menus, not a one-tap 'Cmd-Z for the real world' rail

**Steal for VenueOS**
- STEAL QLab's double-GO protection verbatim for the celebrate/horn/send row: enforce a configurable minimum interval between commits and show an 'armed/cooling' red border so the operator can SEE the console is rate-limited — kills the accidental double-horn/double-celebration (NN/G + QLab).
- STEAL vMix's delta-bound buttons: every score/shot/exclusion stepper is a single dedicated target that encodes team+field+delta (no mode), and mirror them to physical keyboard shortcuts AND a Stream Deck profile so a power operator can drive eyes-up.
- STEAL aviation's two-action forcing function ONLY for the genuinely irreversible/public-disruptive actions (Reset game, clear a period, end-of-game) — a hold-to-confirm (press-and-hold 800ms with a filling ring), NOT a modal dialog. Reserve any confirmation strictly for irreversible actions; everything reversible gets instant undo instead (NN/G: 'go to great lengths to provide undo').
- STEAL the LogRocket reversibility ladder explicitly: map every console action to a recovery tier — high-frequency reversible (score ±1) = NO friction + undo; moderate (exclusion, timeout) = undo + the named Run-of-Show entry; irreversible/public (Reset, All-Clear-equivalent, end period) = hold-to-confirm. Match friction to reversibility, never blanket-confirm.
- STEAL Daktronics' sport-profile model: selecting Water Polo reshapes the console (shot clock 30/20, exclusions/penalty box, sprint cap chips appear) so the operator never configures rules live.
- STEAL Stream Deck's per-button state feedback + color coding: every action button reflects its live state (shot clock running = green, exclusion active = amber count) so status is preattentive and readable in peripheral vision.
- STEAL Doherty/Miller latency budget as a hard spec: every tap must paint optimistic local feedback in <100ms (the score flips instantly on the operator's screen before the network round-trip confirms), with a subtle 'syncing→synced→on-board' state — direct-manipulation control demands <200ms or it stops feeling like control.
- STEAL WCAG 2.2 + Android sizing as a floor, not a target: ≥44px primary targets with ≥8px gaps, and bump destructive/celebrate targets even larger AND spatially separated from benign ones (NN/G proximity rule — don't put 'Reset' next to '+1').
- STEAL debounce discipline: every increment button gets touch-action + tap debounce so 'fast taps register twice' can never double-score under a fast goal sequence.

**Bleeding-edge ideas**
- MODELESS-BY-IDENTITY symmetric panels: instead of fighting the mirror-mode risk, make each team panel carry overwhelming, always-on identity — full-bleed team color as the panel background, logo watermark, jersey-color tint on its own +1 button, and on commit the panel briefly flashes its own color. The operator can NEVER be confused which side they hit because the side announces itself. This beats every consumer scorekeeper.
- THE RUN-OF-SHOW AS THE UNDO MODEL ('Cmd-Z for the real world'): every committed event is a Command-pattern object (execute/unexecute) rendered as a named chip on the bottom rail — 'GOAL Dodgers #7', 'EXCL Sharks #4'. One tap on any chip = instant undo with the board reverting live; the rail IS the multi-level undo history. This is the single highest-leverage differentiator and is server-backed so it survives a reconnect.
- LATENCY-HONEST STATE on every event: each Run-of-Show chip shows a tiny 3-state dot (local → server → on-board/LED-confirmed). The operator can SEE that the goal actually reached the LED ribbon, not just the database — borrowing from broadcast's on-air confirm and solving the 'did it actually go out?' anxiety no scorekeeper app addresses.
- EYES-UP / ONE-HANDED MODE: a thumb-zone-optimized layout variant where the highest-frequency actions (both +1s, clock stop/start, shot-clock reset) collapse into the bottom-third reachable arc, large enough to hit by feel while watching the pool — pair with optional haptic confirmation so the operator gets a tactile 'committed' without looking down.
- ARMED-COMMIT for public irreversibles: a 'celebrate' or 'horn' that's irreversible-on-the-floor uses a guarded two-stage tap (arm → fire) with a visible cooldown, exactly like a red guarded cockpit switch — so the GOAL horn never fires on a fat-finger.
- PEER-CONFIRM HAND-OFF: leverage the existing Hand-off QR so a second phone can mirror the console; the Run-of-Show rail syncs across both, and a head operator can undo a junior's mistake from their own device — Stream-Deck-style multi-operator, applied to error recovery.
- CELEBRATION DRY-RUN GHOSTING: pressing-and-holding a celebrate cue shows a 1-second ghost preview of what will hit the board/ribbon before release commits it — proactive feedback (Buxton's 'determine the mode before the erroneous action') so the operator never fires the wrong cinematic to a live crowd.
