## 1. Top 5 P0 gaps (would embarrass us in front of a real coach)

**P0-A. There is no "Call Timeout" action.** A timeout is an event with deep coupling: pause the game clock, freeze the shot clock and the penalty box, reset the play clock (football) to 25s instead of 40s on resume, decrement the team's timeouts-remaining counter, and (for hockey/basketball) drive a "TIMEOUT" segment label on the broadcast scorebug. Today the operator's only path is to manually click Pause on the clock + manually edit `homeTimeouts` in the stats tray — two separate mutations, none of which decrement timeouts atomically and none of which write a `TIMEOUT` GameEvent for the audit trail. `apps/api/src/sports/sports.service.ts:557-559` seeds `homeTimeouts`/`awayTimeouts` from the sport def's `max`, but there's no `callTimeout(team)` handler anywhere. Daktronics All Sport has a dedicated TIMEOUT key for every sport. P0 for HS basketball / football where timeouts decide playoff games.

**P0-B. The football play clock is not slaved to the game clock.** `setPlayClock` (`sports.service.ts:1463`) is fully independent from `clockAction`. When the operator stops the game clock for a stoppage, the 40-second play clock keeps counting down on its own and never resets to 25 (the correct duration after a stoppage). When the game clock starts again, nothing auto-starts the play clock. `syncShotClockToGameClock` (line 1565) was added 2026-05-27 for the shot clock — there is no equivalent `syncPlayClockToGameClock`. The whole point of the play clock is that it's the snap deadline AND that the ref's whistle resets it; without coupling, the operator must drive both clocks by hand on every snap — unworkable on a real football Friday night.

**P0-C. The CTS bridge silently drops penalty-box, per-team shot-clock, timeouts-remaining, and exclusion data.** `packages/scoreboard-cts/src/parser.ts` decodes `homeExclusions[]`, `awayExclusions[]`, `homeShotClock`, `awayShotClock`, `homeTimeoutsRemaining`, `awayTimeoutsRemaining` from the wire. The bridge body at `CtsBridge.tsx:774-782` only forwards `clockMs`, `clockRunning`, `segment`, `homeScore`, `awayScore`, `horn`, `raw`. `SportsService.cleanCtsSnapshot` (`sports.service.ts:2684-2740`) doesn't even define these fields in its return-type or accept them. Result: water polo's 30s shot clock works only via operator manual entry while the CTS console two feet away is broadcasting the real value. Same for exclusions and per-team timeouts. The whole pitch of CTS integration ("the console drives the board") is half-built.

**P0-D. Possession arrow / basketball possession is only a free-text stat field.** `BASKETBALL` (`sports.ts:188`) and `FOOTBALL` (line 157) each declare `possession` as `type: 'text'` with no validation. The scoreboard render and the ribbon both rely on this stat to drive the possession indicator (the arrow / the football possession LED), but: (a) it's a free-text string the operator types `home`/`away` into manually, (b) no chip in the operator UI flips it on a turnover, and (c) basketball's "alternating possession arrow" (which flips automatically on every held ball after the opening tip) is entirely absent. Daktronics, ScoreVision, and any HS console have a single POSS button that toggles + records to the score-feed. Without this, a HS basketball ref's "arrow flip after the tip" doesn't show on the board unless the operator opens a stat editor mid-game.

**P0-E. End-of-period horn / siren / score-pause coupling never fires.** `autoAdvanceExpiredClocks` (line 1771) rolls the segment when the clock hits 0:00, but writes only `CLOCK { action: 'expired' }` and a SEGMENT event. No CUE is fired (so no horn audio, no "END OF QUARTER" celebration animation, no flash on the ribbon). The shot clock isn't auto-reset on segment change (a basketball Q4 starts with whatever shot clock the Q3 ended at — illegal-but-silent). Penalties don't carry into the next period correctly when the operator manually advances segment (the penalty timer reads continue but the segment-label on the player overlay doesn't update). And when a basketball Q1/Q2 ends with a fouling shot, the shot clock doesn't reset — same for water polo end-of-quarter exclusion carry-over. Pro systems fire a horn cue at 0:00 as the FIRST action; we fire nothing.

## 5. Recommended next 10 commits (prioritized)

1. **[P0, medium]** Add `POST /games/:id/timeout { team, type? }` — atomic: decrement `home/awayTimeouts`, pause game clock, freeze shot clock + penalty box (reuse `syncShotClockToGameClock` + `syncPenaltiesToClock`), reset football play clock to 25s if sport is football, write `TIMEOUT` GameEvent and AuditLog row. Operator console gets a "TIMEOUT HOME / AWAY" button in the ScoreTile.

2. **[P0, small]** Slave the play clock to the game clock: extend `syncPlayClockToGameClock` mirroring `syncShotClockToGameClock` (lines 1565-1600); call it from `clockAction` start/pause AND from `setSegment` and `autoAdvanceExpiredClocks`. On `clockAction` 'start', auto-start the play clock to 40s if armed; on 'pause' freeze it.

3. **[P0, medium]** CTS bridge + `cleanCtsSnapshot` accept exclusions, per-team shot clocks, timeouts-remaining. Replace `shotClock` in the snapshot block with `homeShotClock`/`awayShotClock` (two separate anchors stored in `stats`); merge exclusions into `stats.penalties` with `source: 'cts'`; merge timeouts into `stats.homeTimeouts` / `awayTimeouts`. Edit `CtsBridge.tsx:774-782` body, `sports.service.ts:2684-2740` cleaner, and `cts-merge.ts:144-182` overlay.

4. **[P0, small]** Fire a horn `CUE` from `autoAdvanceExpiredClocks` (line 1771) on every clock-expired event — built-in cue key `'horn'` (add to every clockful sport's celebrations). Sport defs gain `celebrations: [{ key: 'horn', label: 'Horn', emoji: '📯', autoPoints: undefined }]`. The kiosk already renders cues — this is wiring, not new render code.

5. **[P0, small]** Unify the operator/integration paths through one mutation helper. Today `ingest()` writes raw fields; refactor it to call `setSegment` (when segment changes) and `clockAction` (when clock state changes) internally so the sync helpers always run. Bonus: idempotent, well-tested code path for both manual and feed mutations. Closes Invariant #5.

6. **[P0, small]** Wire `applyBaseballCount` strikeout-out and `applySetWin` set-win to `maybeAutoCelebrate`. Look up the sport's celebration where `key === 'strikeout'` or `key === 'setWin'` and call `record(id, 'CUE', ...)` — same shape the manual fireCue uses. Today the `setWin` celebration in volleyball sport def is dead code; this lights it up.

7. **[P1, medium]** Possession arrow as a first-class field (`POST /games/:id/possession { team }`). Add `possession` to the schema (`Game.possession` text col, or store as `stats.possession` but with a typed validator). Operator UI gets a POSS toggle button between home/away tiles. Basketball auto-flip on `STAT_BALL_AWARD` event (held-ball ref signal — leave as manual until we have a held-ball action).

8. **[P1, medium]** Basketball bonus + foul-out automation. When `homeFouls >= 7` set `stats.homeBonus = true`; at 10 set `homeDoubleBonus = true`. Per-player foul tracking via `rosterPlayer.stats.fouls`; auto-emit `FOUL_OUT { playerId }` event at 5. Same shape for wrestling stalling, soccer red-card-on-second-yellow.

9. **[P1, small]** Clamp shot clock at game-clock remaining. In `syncShotClockToGameClock` and `setShotClock`, `ms = Math.min(ms, currentGameClockMs)`. Enforces Invariant #6. Prevents the comical "0:08 left in Q4, 24-second shot clock" display.

10. **[P1, large]** Replace `Game.stats` JSON-blob smear with a typed `GameState` record per sport. Today `stats` is a free-form `Record<string, unknown>` holding `shotClock`, `playClock`, `penalties[]`, `cts`, `homeFouls`, plus the operator's free-text "possession" string. Migrate to a discriminated union per sport-key (Sprint 13's stated goal). Catches every "operator typed wrong key, scoreboard renders zero" failure mode the current system silently swallows. Schema migration is additive (new typed columns, keep `stats` as the fallback), so it's pilot-safe. **This is the architectural fix that unlocks #7-9 cleanly.**

**Bottom line:** the engine has the right shape — an anchor-not-tick clock, signed events, multi-surface fan-out, AUTO celebrations on score deltas — but the per-sport rule layer is a thin veneer. ~85% of the sport-specific scoring/clocking rules a Daktronics All Sport ships out-of-the-box are missing. The two single highest-leverage fixes are #2 (play clock slave) and #5 (unify operator + integration paths) — both small commits, both close Greg's "all the same rules apply" rule directly. After those, #3 (CTS field expansion) unlocks the water polo install we already have hardware for. Items 7-10 are the "looks like a pro system" tier.
