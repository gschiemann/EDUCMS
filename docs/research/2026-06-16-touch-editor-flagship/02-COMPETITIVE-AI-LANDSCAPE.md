# Touch/Template Editor — Competitive + AI Landscape (2026-06-16)

6 parallel web-grounded research agents. Source for the flagship strategy in `01-FLAGSHIP-STRATEGY.md`.

## Consumer design editor + generative-AI design assistant (Canva / Magic Studio / Canva AI 2.0) as the bar for a non-designer-friendly signage template editor

**Products:** Canva editor (web + iOS/iPadOS/Android apps), Canva Magic Studio (umbrella for the Magic AI tools), Magic Design, Magic Write (OpenAI-backed), Magic Switch / Magic Resize, Magic Media (text-to-image, text-to-video), Dream Lab (Leonardo Phoenix image model), Magic Grab + Grab Text, Magic Expand, Magic Edit, Magic Morph, Magic Animate, Brand Kit + Brand Kit Builder + Brand Voice, Bulk Create + Data Autofill, Canva AI 2.0 (conversational/agentic design assistant), Canva Code 2.0 + HTML Import, Template Remix, Canva Sheets + Sheets AI + Magic Charts, Canva AI Connector (ChatGPT/Gemini/Workspace/Teams integrations)

**Standout editor features**
- SMART GUIDES + MAGNETIC SNAPPING: dragging an element shows blue alignment guides to other objects, page center, and margins; elements snap automatically. Hold Cmd/Ctrl to TEMPORARILY bypass snapping for pixel-precise placement — snapping is the default, escape is the exception. Toggle guides with Cmd/Ctrl+; and margins with Cmd/Ctrl+'. This is the single highest-leverage 'it looks designed' mechanic for non-designers (canva.com/design-school/resources/keyboard-shortcuts).
- MULTI-SELECT + GROUP as a unit: Shift+Click to select multiple elements, Cmd/Ctrl+G to group so they move/resize/style together as one. Shift+Arrows to nudge fast. Lets a non-designer manipulate a 'block' (logo+title+subtitle) without breaking its internal layout — directly relevant to VenueOS widget zones.
- MAGIC RESIZE / MAGIC SWITCH (Pro): one design -> instantly reflow into any number of preset sizes/channels in a few clicks ('Copy and Resize' to a target like Facebook Ad); it repositions elements to fit each aspect ratio, not just stretches. Maps 1:1 to VenueOS's need to take one board and emit landscape/portrait/ribbon/LED-canvas variants (canva.com/pro/magic-resize/, futurepedia.io magic-switch lesson).
- BRAND KIT as the spine of the editor: logos, color palettes, fonts, icons, imagery, and pre-approved Brand Templates live in one hub and are one click to apply inside any design; AI tools read from it automatically. 'Apply Brand Kit colors' recolors a whole design to brand palette in one action (canva.com/pro/brand-kit/, canva.com/help/apply-brand-kit-colors/).
- BRAND KIT BUILDER (auto-onboarding): paste a website URL or upload a PDF and AI extracts logos, colors, public fonts — and from PDFs even brand voice/tone and guidelines — to auto-populate the Brand Kit, collapsing manual setup (canva.com/help/brand-kit-builder/). VenueOS already has a branding scrape wizard; Canva's bar is that the SAME extraction also seeds AI tone, not just colors.
- FRAMES & GRIDS: drop any photo into a frame/grid shape and it auto-crops to fit; swap photos by dragging a new one onto the frame. Removes all manual crop/mask work for non-designers.
- MOBILE/TOUCH-FIRST EDITING: full editor on iPhone/iPad with pinch-zoom, swipe, tap, drag gestures + smart guides retained on touch + Apple Pencil support + offline editing. Canva proves a real touch editor (not a cut-down viewer) is achievable — directly relevant to VenueOS operators authoring on iPad.
- ONE-CANVAS UNDO + non-destructive everything: deep undo/redo (Cmd/Ctrl+Z), and AI edits land as normal editable layers you can undo, so users experiment fearlessly. Magic Grab/Grab Text turn baked-in photo content into real editable objects rather than destructive edits.
- TEMPLATE REMIX (Canva AI 2.0, 2026): take any existing template and have AI generate on-brand variations of it — extends a known-good design into many rather than starting blank. Mirrors VenueOS's 'copy a known-good template, don't redesign' rule but automated.

**AI capabilities**
- MAGIC DESIGN (prompt/photo -> full designs): type a short prompt (and/or upload up to ~10 photos/videos) and get 8-12 complete, EDITABLE layouts back; it pulls colors from your media and your Brand Kit, and improves over time from your editing history. This is the flagship 'it builds itself' moment — blank canvas to polished candidates in seconds (canva.com/magic-design/, canva.com/help/use-magic-design/).
- CANVA AI 2.0 — CONVERSATIONAL/AGENTIC DESIGN (Canva Create, Apr 2026): a chat interface where you state a goal/rough brief in plain English ('create a social media campaign', 'adjust the palette to match our brand') and an orchestration layer READS your design, picks the right internal tools (templates, Brand Kit, photo edit, video, Magic Media), and applies edits directly on the canvas — maintaining context as the project evolves across brainstorm->refine->iterate (cmswire.com, techbuzz.ai). This is the new bar: design-by-conversation, not menu-hunting.
- MAGIC WRITE (in-editor text AI, OpenAI-backed): generate copy from a prompt OR highlight existing text -> 'Rewrite' / 'Summarize' / tone shift ('More fun'/'More formal') / 'More like this' / 'This but…' (free-form instruction) -> then Replace / Add below / Copy. Inline, contextual, non-destructive — exactly the pattern VenueOS's sparkle button should adopt (canva.com/magic-write/, canva.com/help/use-magic-write/).
- BRAND VOICE: define brand personality/tone in the Brand Kit; Magic Write and other text AI then generate copy that matches how the business communicates — so generated text is on-brand by default, not generic (canva.com/help/brand-kit-best-practices/).
- MAGIC MEDIA / DREAM LAB (text-to-image, text-to-video): generate images in many styles (photo, 3D, neon, concept art) and short video clips from a prompt; Dream Lab is the higher-quality image model (built on Leonardo Phoenix). Credit-metered (1 credit/image). Lets a non-designer create bespoke hero imagery without stock hunting (canva.com/ai-image-generator/, croma.com Dream Lab).
- MAGIC GRAB + GRAB TEXT: one click lifts a person/object OUT of a flat photo into a movable/resizable/editable layer (Magic Grab), or turns text baked into an image into a real editable text box you can restyle (Grab Text). Turns 'locked' raster content into editable design elements (canva.com/help/using-magic-grab/, canva.com/features/edit-text-in-image/).
- MAGIC EXPAND (outpaint) + MAGIC EDIT (inpaint/replace): Magic Expand extends a photo in any direction to fit a new aspect ratio without losing quality; Magic Edit adds/removes/replaces objects via a brush + text prompt. Both solve 'this image doesn't fit my layout' for non-designers (canva.com newsroom/Magic Studio).
- MAGIC ANIMATE (one-click motion): AI identifies every element and applies coherent animations/transitions whose style and TIMING are auto-matched to the content, fonts, images, and colors — a whole deck/board comes alive in one click. Strong pattern for VenueOS celebration/transition motion 'just appearing' (canva.com/design-school/resources/magic-guide-magic-animate).
- MAGIC MORPH: select a text box or shape, describe a look ('neon lettering', 'grass texture'), and AI restyles that element into the described treatment — turns a plain shape into a themed graphic from words (Magic Studio).
- BULK CREATE + DATA AUTOFILL: design one template, connect named fields to a CSV/XLSX/Canva Sheet (or a live data app via API), and generate N personalized designs at once (mail-merge for design); Data Autofill keeps a single brand template populated from live data. This is the 'data -> finished boards' engine VenueOS needs for menu/roster/per-location signage (canva.com/help/bulk-create-data-autofill/, canva.com/help/data-autofill/).
- AI CONNECTOR / DISTRIBUTED AI: Canva exposes APIs so external assistants (ChatGPT, Gemini, Teams, Google Workspace) can generate designs that obey a company's brand spec — meeting users where they already work (canva.com/ai-connector/). Relevant to VenueOS's Integration Concierge ambition.

**Magic-moment UX**
- BLANK BOX -> 8-12 FINISHED BOARDS in one prompt: user types one sentence, gets a wall of complete, on-brand, editable designs to pick from. The magic is the immediate sense of 'I already have something good' — zero blank-canvas paralysis.
- SELECT TEXT -> TONE CHIP -> DONE: highlight a sentence, tap 'More formal', the copy rewrites in place; accept with one tap. The AI lives ON the thing you're looking at, with instant preview and trivial accept/undo.
- ONE-CLICK 'BRING IT ALIVE': Magic Animate animates an entire board with timing and motion auto-matched to its content in a single click — motion design with zero motion-design skill.
- DESCRIBE THE CHANGE, WATCH IT HAPPEN: in Canva AI 2.0 you type 'make the palette match our brand' or 'add a hero photo of our team' and the agent reads the design and applies the edit on-canvas — conversation replaces menu archaeology.
- LIFT A PERSON OUT OF A PHOTO IN ONE CLICK: Magic Grab makes a locked subject suddenly draggable/resizable — a visceral 'whoa, it's editable now' moment.
- PASTE YOUR WEBSITE -> INSTANT BRAND KIT: URL or PDF in, logos+colors+fonts+voice out, and the next design is already on-brand without any setup.
- ONE DESIGN -> EVERY SIZE INSTANTLY: Magic Switch/Resize spits out platform-perfect variants in a few clicks; the relief of 'I don't have to rebuild this 6 times' is the magic.
- ONE TEMPLATE + A SPREADSHEET -> HUNDREDS OF FINISHED DESIGNS: Bulk Create turns rows into ready boards; the operator never touches the individual designs.

**Patterns to steal**
- INLINE CONTEXTUAL AI ON THE SELECTED OBJECT, not a separate modal: select text/element -> a small action menu offers Rewrite/Summarize/Tone/'This but…' -> Replace / Add below / Copy. VenueOS's sparkle should become this: click a widget's text, get tone/length/rewrite chips inline, preview in place, one-tap accept — leveraging the existing click-to-edit hot-zone shim that already reports which element was clicked.
- RETURN MULTIPLE EDITABLE CANDIDATES, never one: Magic Design returns 8-12 full layouts the user picks from. VenueOS's Touch Template Generator should return a GRID of 6-12 editable drafts (different layouts/themes for the same brief), not a single result — choice + 'pick the winner' is the proven non-designer flow and mirrors VenueOS's own HTML-mockup design loop.
- BRAND KIT AS THE DEFAULT, AI READS IT AUTOMATICALLY: every AI output (copy, images, layouts, recolors) silently honors logo/palette/fonts/voice. VenueOS already resolves var(--brand-primary)/var(--brand-accent); extend so AI generation, copy tone, and recolor-this-board ALL pull from the brand kit + a stored 'brand voice' string by default — no extra step.
- ONE-CLICK 'APPLY BRAND' / RECOLOR WHOLE DESIGN: a single action that recolors an entire board to the brand palette. VenueOS should ship a 'Brand this board' button on every template (it has the brand-apply plumbing) and make it a first-class one-tap, with a shuffle to cycle palette assignments.
- MAGIC SWITCH = ONE BOARD -> EVERY SURFACE: auto-reflow a design into landscape/portrait/ribbon/per-LED-canvas-size variants, repositioning (not stretching) elements. This is a killer fit for VenueOS's multi-resolution player targets (4K landscape, 2160x3840 portrait, 320x1080 ribbon, N-panel daisy-chain) — author once, emit all.
- BULK CREATE / DATA AUTOFILL FROM A TABLE OR LIVE FEED: one template + a data source -> N finished boards. VenueOS should let an operator bind widget fields to a CSV or a live POS/roster/menu feed and generate per-location/per-player/per-item boards in one action (auto-86 and per-location pricing already prove the live-data plumbing).
- AUTO BRAND/VOICE EXTRACTION AT ONBOARDING: paste a URL or upload a PDF -> extract logos, colors, fonts AND tone-of-voice to seed both the visual brand kit and the AI's writing voice. VenueOS's branding scrape should also capture a 'brand voice' descriptor that feeds the copy AI.
- TEMPLATE REMIX (extend a known-good design, don't start blank): let AI generate on-brand VARIATIONS of an existing flagship template. This operationalizes VenueOS's own 'copy Rainbow Ribbon, don't batch-build new' rule — safer than blank-slate generation and avoids the 'rounded rectangle with shadow' regression.
- SNAP-BY-DEFAULT, ESCAPE-TO-FREE-PLACE: magnetic snapping to other objects/center/margins with a Cmd/Ctrl override for precision. VenueOS's zone editor should snap zones to each other, canvas center, and a margin grid by default, with the same modifier escape hatch — the cheapest way to make non-designer layouts look intentional.
- NON-DESTRUCTIVE 'LIFT TO EDITABLE': Magic Grab/Grab Text turn baked raster content into real layers. For VenueOS EXTERNAL_HTML boards, the analog is making every visual element click-to-edit (already the shim's job) AND offering 'extract this as an editable widget' so imported flat designs become editable.
- AGENTIC GOAL->DESIGN AS THE TOP-LEVEL ENTRY: Canva AI 2.0 makes 'describe your goal' the front door and orchestrates tools behind it. VenueOS's Integration Concierge + Touch Template Generator should merge into one conversational front door: 'I run a pizza shop, make me a menu board wired to my POS' -> it discovers POS, seeds template, binds live price/auto-86 — the 'it almost makes itself' moment.

**Where we can leapfrog**
- LIVE DATA + SIGNAGE-NATIVE BULK CREATE: Canva's Bulk Create is one-shot batch generation; VenueOS can do CONTINUOUS data binding — a board that re-renders as POS price/auto-86/roster/score feeds change in realtime. Canva makes static files; VenueOS makes living screens. Make 'bind any widget field to a live feed' a first-class editor action.
- AUTHOR-ONCE FOR REAL HARDWARE TARGETS: Canva's Magic Resize targets social sizes; VenueOS can Magic-Switch into actual deployment surfaces — 4K landscape, portrait, ribbon (320x1080), N-panel daisy-chain LED canvases, and Taurus-safe CSS — with per-target layout rules. No consumer tool reflows for LED ribbon hardware.
- EMERGENCY/SAFETY-AWARE GENERATION: no design tool understands life-safety. VenueOS AI can generate boards that already include compliant emergency overlay zones, severity styling, and aria-live regions by default — a category Canva will never enter.
- VERTICAL-AWARE AGENTIC CONCIERGE: Canva AI orchestrates generic design tools; VenueOS can orchestrate INTEGRATIONS — 'I run a gym' -> discover the POS/streaming/scheduling stack, wire it, and seed a board bound to that live data. 'It builds itself' end-to-end including the plumbing, which Canva does not do.
- SPORTS GAME-PRESENTATION GENERATION: describe a scoreboard/ribbon/celebration in a sentence -> AI assembles per-sport widgets, score bindings, and celebration decks. A wholly uncontested space for a conversational design front door.
- BRAND-VOICE PER VERTICAL OUT OF THE BOX: ship pre-tuned brand voices per vertical (school announcement vs gym hype vs QSR promo vs worship) so even tenants who never configure voice get appropriately-toned copy — Canva requires manual voice setup.
- PROVABLY-ON-DEVICE-SAFE OUTPUT: AI generations can be auto-validated against the Chromium-83/Taurus + WebKit constraints VenueOS already encodes (no inset shorthand, no risky gap, auto-fit floors), so generated boards are guaranteed to render on the customer's actual screens — a correctness guarantee no consumer tool offers.

**Pitfalls**
- AI features are heavily gated behind Canva Pro and metered by credits (e.g., free Magic Design ~10 uses/LIFETIME; image gen 1 credit each; text-to-video Ultra tier). VenueOS must decide its own metering carefully — its 3-tier model (platform setup AI / BYOK creative / managed) is sound, but the operator-facing experience must never dead-end at 'out of credits' mid-task; degrade gracefully like the existing 'Configure your AI provider' message.
- Conversational/agentic design (Canva AI 2.0) is a 2026 research-preview rolled out to a limited cohort first, paid-only — it is NOT yet a mature, universally-available baseline. Don't assume it's a finished, copyable spec; treat the inline-contextual + multi-candidate patterns (proven, shipping) as the safe bar, and the full agentic front-door as the aspirational target.
- Multiple sources conflict on launch dates/branding (Magic Studio Oct 2023/2025 vs Canva AI 2.0 Apr 2026); Canva ships fast and renames features. Cite features by behavior, not by a fixed version number, and re-verify before quoting dates externally.
- Auto-resize/Magic Switch still often needs 'minor adjustments to realign elements' after reflow — even Canva's best reflow isn't perfect. VenueOS's multi-target reflow will need a human-review step and snap-to-grid cleanup, not blind auto-emit.
- Canva text AI is OpenAI-backed and image AI uses Leonardo/partners — they buy best-in-class models rather than build all in-house. VenueOS's BYOK/multi-provider approach is aligned; the lesson is invest in the UX/orchestration layer (where Canva's real moat is), not in training models.
- Magic Animate's auto-motion can be generic if content is sparse; one-click motion is a great default but power users need to override per-element. Ship the one-click default AND keep granular control.
- Canva.com aggressively blocks automated fetching (403 on WebFetch across help/newsroom pages) — claims here are corroborated via official pages surfaced in search snippets plus independent course/news writeups; a few exact UX wordings come from third-party tutorials and should be spot-checked against the live product before being treated as pixel-exact.

## figma-adobe-msft — pro-editor layout intelligence (auto-layout/constraints, components/variants, responsive reflow) + AI generation UX (text-to-template, first-draft generation, brand-aware autofill, replace-content, resize/Magic-Switch). Grounded in Figma AI/Auto-Layout, Adobe Express + Firefly, Microsoft Designer, with Canva as the consumer-grade comparator.

**Products:** Figma (First Draft, Make, AI Grid, Auto Layout 5.0, Components/Variants/Properties, Rename layers, Replace content, image-AI actions, Dev Mode), FigJam (Figma's whiteboard, shares the Figma AI surface), Adobe Express + Adobe Firefly (text-to-template, Generative Expand, Resize with focal point, Bulk Create, Firefly Custom Models), Microsoft Designer + Microsoft 365 Copilot (prompt-to-design, Brand Kit / Official Brand Kits, in-app PowerPoint/Word generation, DALL-E imagery), Canva (Magic Design, Magic Resize / Magic Switch, Brand Kit) — consumer-grade comparator for the magic-moment bar

**Standout editor features**
- Figma Auto Layout is the single most important pro-editor mechanic to borrow: a frame gets a flow direction (vertical / horizontal / grid, plus a 'wrap' toggle on horizontal), a gap-between value (fixed number OR 'Auto'/space-between), and per-side padding. Every child then declares a resizing mode — Fixed, Hug contents (shrink to fit children), or Fill container (stretch to fill). When content is added/removed/resized, the frame reflows with zero manual repositioning. This is exactly the layout intelligence VenueOS zones lack today (zones are absolute x/y/w/h %). https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout
- Auto Layout 5.0 adds min/max width and height constraints on Hug and Fill children — so a 'Fill' element can grow but never exceed a max, and a 'Hug' text block can shrink but never below a min. This is the cleanest known primitive for VenueOS's recurring auto-fit/≥50px-floor problem: instead of post-hoc scale math, declare a min font/element size as a constraint and let the layout engine respect it. https://help.figma.com/hc/en-us/articles/18894664907287-Create-a-responsive-card-with-auto-layout-and-constraints
- Constraints (separate from Auto Layout) pin an absolutely-positioned child to its parent's left/right/top/bottom/center/scale as the parent resizes — the mechanism Figma uses for true responsive reflow across screen sizes. For VenueOS this is the model for one template auto-adapting from a 1920x1080 landscape zone to a 320x1080 LED ribbon or a portrait kiosk without a hand-built second layout. https://thecodeaccelerator.com/blog/constraints-responsive-design-figma
- 'Ignore Auto Layout' (formerly Absolute Position) lets a single child opt out of the flow and be free-positioned while still living inside the auto-layout frame — the escape hatch that makes auto-layout usable for real designs (e.g. a badge pinned to a corner of a reflowing card). VenueOS needs the same: mostly-managed layout with per-widget absolute overrides. https://help.figma.com/hc/en-us/articles/360040451373-Guide-to-auto-layout
- Figma Components + Variants + Component Properties (Boolean show/hide, Instance Swap, Text) collapse what would be 18+ hand-built variants into a few smart components with toggleable properties — e.g. one 'menu item' component where a Boolean hides the price, an Instance Swap changes the icon, a Text property sets the label. Directly maps to VenueOS's per-vertical widget sets and 107 HTML boards: one parameterized board component instead of N near-duplicate files. https://blog.logrocket.com/ux-design/using-component-properties-figma/
- Nested auto-layout frames (each with its own direction/padding/gap) compose into arbitrarily complex responsive layouts — a horizontal header frame inside a vertical page frame inside a grid. This nesting model is how to make VenueOS templates structurally robust against text-overlap/broken-layout regressions instead of pixel-tuning each zone. https://designilo.com/2025/07/08/creating-responsive-layouts-in-figma-with-auto-layout-5-0/
- Canva Magic Resize / Magic Switch: one button re-targets a finished design into many sizes/formats AND can convert format (poster->presentation->social) or language, adapting content to the new aspect ratio rather than naively scaling. The flagship pattern VenueOS should own: 'design once, deploy to landscape board + portrait kiosk + LED ribbon + scorebug' from a single source. https://www.canva.com/pro/magic-resize/
- Adobe Express Resize with focal-point control + Generative Expand: when resizing changes the aspect ratio, it preserves the most important part of the image (focal point) and AI-fills the newly-exposed area instead of letterboxing or cropping blindly — the right answer for VenueOS images reflowing between a wide ribbon and a tall portrait zone. https://helpx.adobe.com/express/web/bulk-create-and-automate/bulk-create.html

**AI capabilities**
- Figma First Draft (text-to-design): the operator types intent ('a pricing page for a developer-tools startup'), optionally picks a library fidelity (lo-fi wireframe vs high-fidelity), clicks 'Make it', and gets a high-fidelity frame WITH auto-layout applied and organized/named layers — explicitly a 'jumping-off point', not a finished artifact. Architecture worth copying: model + CONTEXT (a curated component library) + prompt; the AI selects/arranges/customizes real library components rather than free-painting pixels, so output is editable structure not a flat image. https://www.figma.com/blog/figma-ai-first-draft/
- First Draft post-generation 'quick actions' are the real magic moment: after generation, one-tap actions switch theme, adjust spacing, change border-radius, or apply further natural-language edits, and the AI regenerates content variations while keeping design consistency. This 'generate-then-nudge-with-chips' loop (not re-prompt-from-scratch) is the interaction VenueOS's Touch Template Generator should adopt. https://help.figma.com/hc/en-us/articles/23955143044247-Use-First-Draft-with-Figma-AI
- Figma 'Rename layers' AI names every layer from its content, location, and relationship to sibling layers in one click — and auto-applies the same name to matching layers across all top-level frames. For VenueOS this is auto-naming/auto-tagging generated zones+widgets so a non-technical operator sees 'Lunch price' not 'Text 14'. https://help.figma.com/hc/en-us/articles/24004711129879-Rename-layers-with-AI
- Figma 'Replace content': swaps placeholder/duplicate text for unique, realistic content automatically, refinable with a follow-up prompt — useful for instantly populating a freshly-generated template with believable copy so the operator sees a real-looking board, not lorem ipsum. https://help.figma.com/hc/en-us/articles/23870272542231-Use-AI-tools-in-Figma-Design
- Adobe Express text-to-template (Quick actions > Generative AI): describe the design -> get EDITABLE templates (separate text/image layers you can keep customizing), not a baked image. The key differentiator vs a raw image generator is that the output is a real editable document. https://helpx.adobe.com/express/web/create-with-templates/text-to-template.html
- Adobe Firefly Custom Models / brand training: an org trains a model on its own logos, type, color, and imagery style so EVERY generation comes back on-brand by construction — natively wired into Adobe Express. This is the strongest version of brand-aware AI: brand isn't a post-filter, it's baked into the generator. VenueOS's per-tenant brand kit (var(--brand-primary)/accent) is the seed for this. https://business.adobe.com/products/firefly-business/custom-models.html
- Microsoft Designer brand-aware generation: a Brand Kit (hex palette, typefaces, logos) is set once and the AI auto-maps those constraints across every generated template; 2026 'Official Brand Kits' in M365 Copilot enforce palette/typography/brand-voice on all employee generations org-wide. Pattern for VenueOS: brand kit auto-applied to AI output AND enforceable as a guardrail for non-designer staff. https://www.aitools-directory.com/tools/microsoft-designer-ai-powered-graphic-design-tool/
- Microsoft Designer / Copilot 'describe your idea in words' lives INSIDE the host app (PowerPoint, Word) — generation without context-switching. For VenueOS this argues for the AI build-it-for-me to live inline in the template editor and even inline per-zone, not behind a separate modal. https://www.microsoft.com/en-us/microsoft-365/microsoft-designer
- Adobe Express / Firefly Bulk Create: upload a CSV (each row = one variation, up to 99 in Express / up to 10,000 in Firefly), map columns to swap text/image slots, and mass-generate on-brand variants; Firefly bulk also resizes and replaces backgrounds at scale. This is the data-merge engine VenueOS already needs for per-location menu boards (50 locations x per-location price/availability) and per-sport scorebugs. https://helpx.adobe.com/express/web/bulk-create-and-automate/bulk-create-generate.html
- Figma image-AI suite usable per-asset inside the editor: Make/edit image from prompt, Remove background, Boost resolution, Expand (outpaint), Isolate/Erase object, Vectorize raster->editable vectors. Each is a right-click 'Action' on a selected element. VenueOS could expose the same per-asset action menu so operators fix logos/photos without leaving the board. https://help.figma.com/hc/en-us/articles/23870272542231-Use-AI-tools-in-Figma-Design

**Magic-moment UX**
- Type one sentence -> watch a high-fidelity, ALREADY-AUTO-LAID-OUT, organized-and-named editable board appear in ~2 minutes (Figma First Draft). The 'wow' is that it's editable structure with sensible layer names, not a screenshot. https://www.figma.com/blog/figma-ai-first-draft/
- After the board appears, tap chips — 'switch theme', 'adjust spacing', 'change corner radius', 'try variations' — and watch it restyle in place while staying coherent. The operator never re-types the prompt. https://help.figma.com/hc/en-us/articles/23955143044247-Use-First-Draft-with-Figma-AI
- One 'Magic Resize/Switch' click turns a poster into a presentation/social/other-size set, re-flowing content to each new aspect ratio — multi-format campaign in seconds. https://www.canva.com/pro/magic-resize/

**Pitfalls**
- Tome SUNSET its AI presentation product (Apr 30 2025) despite 20M users / $81.6M raised — ARR stayed under $4M because users loved the free novelty but wouldn't pay. LESSON: novelty AI generation alone doesn't monetize; the durable value is EDITABILITY + ON-BRAND + LIVE-DATA + reliability, not the wow of first generation. https://www.sunsethq.com/layoff-tracker/tome / https://deckary.com/blog/tome-review
- Flat / dead-end output is the #1 thing every survivor markets AGAINST. If AI returns something the operator can't deeply edit, it's worthless — Uizard/Stitch/Relume all lead with 'fully editable, not a flat image.' VenueOS must guarantee generated boards land as real editable widgets/zones, never baked images. https://uizard.io/autodesigner/
- AI output HOMOGENIZES: Stitch reviewers found 'design homogeneity — visually similar designs despite varied prompts' and 'familiar layout patterns.' Generating from a small template vocabulary regresses to sameness — the same 'rounded-rectangle-with-shadow' trap CLAUDE.md already warns about. Mitigate with multiple genuinely-distinct variations + theme diversity + reference-driven design. https://blog.logrocket.com/ux-design/i-tried-google-stitch-heres-what-i-loved-hated/
- Generated layouts often fail accessibility + responsiveness (Stitch: 'frequently fail basic WCAG color contrast and touch targets,' 'static non-responsive layouts requiring manual breakpoint fixes'). For signage on a fixed-distance 8-ft-viewing LED wall this is fatal — AI output must pass contrast + min-font-size + Taurus-safety by construction, not as cleanup. https://blog.logrocket.com/ux-design/i-tried-google-stitch-heres-what-i-loved-hated/
- Custom-template fidelity is genuinely hard: Copilot users report friction generating onto org-specific custom templates vs the built-in ones. VenueOS's promise is brand-fidelity, so test AI generation against real customer brand kits, not just the demo theme. https://learn.microsoft.com/en-us/answers/questions/5515849/
- Cost/quota discipline: every tool meters AI hard (Gamma card caps free=10/pro=60; Durable 'AI employee chat' quotas; VenueOS's own 30/hr/tenant). Generation + edit-by-chat + N-variations multiply spend fast — keep the platform-funded Concierge tier and customer-BYOK creative tier strictly separated (already a VenueOS rule) or margins evaporate. https://kripeshadwani.com/gamma-app-review/
- Free-loved-but-unpaid is a real risk (Tome): wow-factor generation drives signups but the willingness-to-pay lives in the boring durable stuff (live integrations, fleet push, reliability). Anchor the AI editor's value to those, not to the generation demo.

This converts VenueOS's static widgets into interactive ones without a new architecture.
- Interface Assets that self-wire: ship composite interactive components (browsable Grid, Carousel, Pinboard, accordion Directory, before/after slider, tabbed Menu) where dropping one yields working scroll/select/detail behavior — operator only swaps content. Mirrors Intuiface's biggest UX lead.
- Multi-scene + master/experience layers: build the scene runtime on VenueOS's roadmap (#241-243) with a persistent layer for home/back/language/attract-reset so every kiosk gets consistent chrome for free.
- Attract loop + idle→interactive as a first-class TEMPLATE SETTING: NN/G and museum guidance both say idle kiosks must run a vibrant attract mode with subtle motion ('practically shouting come learn'), then reset to home on timeout. Make 'attract template' + 'idle timeout (default 30-60s) + Are-you-still-there? countdown + one-tap session reset' built-in fields on any touch template, not hand-built. (nngroup.com/articles/very-large-touchscreen-ux-design; kioskmarketplace.com; touchhalloffame.us)
- Variations-not-blank-canvas: Rise Vision returns 3 design options from one prompt; have VenueOS's Touch Template Generator always return 3 distinct interactive drafts to pick from.
- Single-task screens + progressive disclosure + persistent cart/home in fixed location: the cross-brand QSR teardown's winning principles — enforce them as template-builder guardrails/lints (one primary action per scene, back/home/cancel always visible). (seenlabs.com mcdonalds-vs-taco-bell teardown; avixa kiosk checklist)
- BrightAuthor-style visual state diagram for advanced users: a node-graph view of scenes+transitions alongside the simple WHEN/THEN panel, so power users see the whole flow. (docs.brightsign.biz)
- Reach Mode toggle baked into every kiosk template: McDonald's lowers the entire UI to the bottom third for wheelchair/short users via one button — make it an auto-generated accessibility control, not bespoke. (swiftforcetech.com; vispero/TPGi)
- Mobile-as-controller / QR handoff: Intuiface lets the kiosk hand a session to the visitor's phone via QR (take-home info, controller). VenueOS could uniquely tie this to its tenant data (order, directory entry, emergency map).

**Where we can leapfrog**
- INTERACTIVE + EMERGENCY on the same screen, the same authoring tool: NO interactive-kiosk builder (Intuiface/BrightSign/Rise/22Miles) has native life-safety. A VenueOS interactive kiosk could, on lockdown, auto-swap every scene to the nearest evacuation route + hold-instructions — the wedge from CLAUDE.md applied to touch. Owns a category none of them touch.
- AI that authors interaction LOGIC from a sentence, not just content: competitors generate slides/structure; none publicly generate the trigger/action graph ('tapping a dept zooms its floor + shows hours'). VenueOS's existing Touch Template Generator + click-to-edit shim + variants-register is the foundation to be FIRST to ship NL→interactive-flow with 3 pickable drafts.
- Touch-UX LINTER as a default: auto-flag tap targets <44px, elements outside 15-48in reach, missing home/back/cancel, no idle reset, color-only state, contrast < WCAG AA, gestures that require pinch/drag. No competitor markets an accessibility/ergonomics linter; VenueOS already has a StyleableField + CI-gate culture to do it. (grounded in avixa/NN-G/TPGi specs)
- One-tap Reach Mode + full ADA/EN-301-549 accessibility GENERATED into every touch template (screen reader, audio, high-contrast, timeout extension, keypad nav) — turn a lawsuit-class hazard into a built-in, since rivals leave it bespoke.
- Wayfinding as a native Interface Asset tied to VenueOS's existing floor-plan upload (#54/#200) + fleet geo data: ingest the floor plan, drop POIs, draw ADA routes, drive kiosk AND mobile from one back end (the 22Miles model) — and reuse the SAME floor plan for emergency evacuation routing. Double-duty no rival has.
- Vertical-aware interactive starters: VenueOS already has per-vertical widget packs + Integration Concierge. Ship interactive templates wired to live tenant data on day one — QSR self-order pre-wired to the connected POS (price + auto-86), museum Lift-&-Learn, school interactive directory, lobby check-in — so 'it almost makes itself' is real because the data is already connected.
- QR/mobile handoff bound to tenant data: hand the kiosk session to the visitor's phone — order, directory result, OR live evacuation map during an incident. Uniquely powerful because VenueOS owns both the screen and the alert layer.
- Self-personalizing runtime content scoped to VenueOS data: AI rewrites kiosk copy per location/time/audience using already-connected POS/menu/schedule feeds (Intuiface needs you to wire the API; VenueOS can pre-wire it via the Concierge).

**Pitfalls**
- Tap targets too small / crowded: min 44×44px (Apple) / 48×48dp (Material); PUBLIC kiosks need MORE — 9-12mm finger targets per AVIXA, up to 12-15mm for diverse populations (ISO), with 5-8mm spacing (ISO 9241-411) which cut error rates 40-60%. VenueOS's StyleableField lets operators shrink buttons below this; the builder should warn. (uxuiprinciples.com; smashingmagazine.com tap-target cheatsheet; avixa)
- Gestures that fail on large/standing screens: NN/G found drag/swipe/flick/pinch are physically strenuous and inaccurate at arm's length (90° wall-mount worst); TAP is the only reliable primitive. Don't author touch flows that REQUIRE pinch/drag. Mount at ~45° to signify touch + add privacy. (nngroup.com)
- Reach/ergonomics ignored: interactive elements must sit in the 15-48in-from-floor zone for wheelchair + standing reach; large screens have a 'field-of-view paradox' where elements are hard to even notice — make them big with attractor motion. (avixa; nngroup.com)
- Accessibility = lawsuit risk: kiosks must be ADA/Section 508/EN 301 549 compliant — Reach Mode, screen reader + audio, headphone jack, high-contrast/large-text, color-not-sole-indicator, timeout EXTENSIONS, keypad/tactile alternative. Lawsuits have been filed over non-compliant QSR kiosks. (vispero/TPGi; grubbrr 2026 guide; intouchinsight)
- Upsell/interruption overload: McDonald's loses to Taco Bell by prompting after nearly every item + interrupting payment with loyalty asks — feels aggressive. Cap to one consolidated upsell + one summary; running total always visible. (seenlabs teardown)
- Hidden customization + unclear navigation: McDonald's buries modifiers in multi-step flows with weak search and too many top-level categories. Keep customization a simple toggle list with easy reversal; one task per screen. (seenlabs teardown)
- No idle reset / stale last-screen: kiosks left on the last user's screen or a dim screensaver kill the next visitor; need attract mode + countdown + one-tap reset. (kioskmarketplace.com; touchhalloffame.us)
- Sandboxed-iframe architecture limits true interactivity: VenueOS's EXTERNAL_HTML boards run in null-origin sandboxes where React can't reach in (per CLAUDE.md) — fine for apply+click-to-edit, but a rich multi-scene interactive runtime (scene transitions, shared session/cart state, sensor input) likely needs the native scene runtime on the roadmap, not the iframe shim.
- Privacy on public touch: vertical public screens have only 'privacy of scale' — never collect sensitive input (PII, payment) on an open-facing kiosk without angle/shielding. (nngroup.com)

## AI co-creation / "it builds itself" interaction patterns for a digital-signage touch & template editor — multimodal input, chat-to-edit, generate-then-refine, brand extraction, data auto-fill, magic reformat, and proactive suggestions, with editability/brand-drift/latency/cost pitfalls.

**Products:** Canva (Magic Design, Magic Resize/Magic Switch, Magic Write, AI 2.0 conversational/agentic editing, in-house design model with editable layers, Brand Kit Builder URL/PDF extraction, art-style copy), Adobe Express AI Assistant (beta, Oct 2025 — conversational two-mode editing, inline suggestions, per-layer edits, reformat-by-conversation) + Adobe Firefly Style Kits / Custom Models, Figma First Draft → Figma AI agent (text→editable mockup with auto-layout + design-system-grounded layers) + Figma Make, Microsoft 365 Copilot / Designer (Brand Kit with brand voice, Brand Checker, Edit with Copilot, branded-visual generation), Google Stitch (formerly Galileo AI) and Uizard (sketch/screenshot → editable hi-fi design, Figma/HTML handoff), OptiSigns AI Designer + OptiDev (signage-native prompt→multi-design→full-editor; describe→interactive kiosk/dashboard/data-app connecting Stripe/Shopify/BigQuery/SharePoint), Rise Vision AI design tool (K-12 signage: prompt → 3 editable designs → schedule; 750+ templates), Yodeck Smart Engine (business-type layout suggestions, AI-managed/daylight-optimized playlists), BrightSign brightAuthor AI toolkits + Quividi (audience-aware content), Navori / AIScreen (data-driven content automation), Puck (Puck AI — constrained generation into a React component registry / validated schema)

Backed by Canva's OWN foundational design model that generates designs with EDITABLE LAYERS AND OBJECTS rather than flat images, plus 'living memory' and 'layered object intelligence' so iterative edits don't blow away the rest of the design (canva.com/help/canva-design-assistant, techcrunch 2025-10-30, canva.com/newsroom/news/canva-create-2026-ai).

Reformat-by-conversation: 'make this design work for Instagram Stories' → auto-resizes, reformats, adjusts typography for the new aspect. (helpx.adobe.com/express/web/ai-assistant, news.adobe.com 2025-10-28).

**AI capabilities**
- Multimodal input as the front door — every leader now accepts text prompt OR image/logo/media upload OR website URL OR sketch/screenshot, not just text. Canva Magic Design and Brand Kit Builder both take a URL/upload; Uizard/Stitch take sketches and screenshots. For signage the killer on-ramps are: photograph an existing physical sign/paper menu → editable board, and paste-your-website → brand+first-board.
- Chat-to-edit over an existing design (not just generate-from-scratch). The agent must READ the current canvas state, resolve a natural-language instruction to specific layer/field mutations, and apply them — Canva AI 2.0 and Adobe Express AI Assistant both do this; the differentiator is editing IN PLACE while preserving everything else ('layered object intelligence' / 'keeping the rest of the design intact').
- Generate-then-refine with multiple options. Rise Vision returns 3 designs; Canva Magic Design returns a selection; Adobe surfaces inline alternatives. Showing N options (not 1) plus an obvious 'regenerate / try another' beats a single take and de-risks bad output.
- Editable-layers output, never flat images. The single biggest architectural commitment: Canva built its own design model specifically so output has editable layers/objects; Figma First Draft emits auto-layout + organized layers grounded in your design system. Flat-render output is the #1 failure that makes AI features useless after the wow.
- Brand extraction + brand-grounded generation. Auto-pull palette/fonts/logo/voice from a URL or PDF (Canva Brand Kit Builder), then INJECT that brand context into every generate/edit call so output is on-brand by default (Microsoft Copilot Brand Kit, Adobe Style Kits). Includes a Brand Checker that flags off-brand results.
- Magic resize / reformat across aspect ratios via AI (not naive scaling) — Canva Magic Resize/Magic Switch and Adobe Express reflow text, reposition, and re-typeset for a new shape. For signage this is THE high-leverage one: same board auto-adapted to 16:9 TV, portrait poster, and a long ribbon/LED strip.
- Data-aware / auto-fill content — templates linked to live data (POS prices, weather, RSS, inventory, schedules) that AI both wires up and writes copy for (Navori, AIScreen, Rise Vision data-driven automation; OptiDev connects Stripe/Shopify/BigQuery). 'AI-from-CMS-data': generate menu copy from the POS feed, schedule descriptions from the calendar.
- Proactive / contextual suggestions surfaced in-context (Adobe inline suggestions above the input box; Canva @-mention the AI in comments for suggestions). The system offers next-best-actions ('this text is too small for 8-ft viewing', 'add your logo', 'this board has no emergency fallback') rather than waiting to be asked.
- Constrained generation into a known component/schema registry (Puck AI pattern): the model assembles from a FINITE registry of approved components and emits VALIDATED JSON SCHEMA, not arbitrary markup — guaranteeing design-system compliance, deterministic-enough output, and zero post-gen refactor. This is the architecturally correct way to make AI output editable and on-brand by construction.
- Style/art-style transfer — Canva AI can 'copy the art style of any design' and apply it; the 'make a matching set / match this look' capability for building a coherent multi-board playlist.

**Magic-moment UX**

- Designed one 16:9 TV board, now need it for the portrait kiosk and the long LED ribbon: one tap on 'Reformat' and AI re-typesets and repositions all three — not a squished scale, an actually-laid-out version per shape. (Canva Magic Resize/Switch + Adobe 'make this work for Stories'.)
- Snap a photo of your paper menu (or your old foamcore sign) → it comes back as an editable digital board with your items, prices, and sections as real widgets. (Uizard/Google Stitch screenshot-to-editable-design, grounded in VenueOS's widget registry.)

**Patterns to steal**
- Generate INTO your existing schema, not into pixels. VenueOS already has the perfect substrate: TemplateZone widgets with typed config, a variants-register, and StyleableField. Make the Touch Template Generator emit the SAME zone/widget JSON the editor already renders and edits — this is exactly Puck AI's 'constrained generation → validated schema' pattern and it guarantees every AI output is click-to-edit on day one (no flat-image trap). This is your structural moat vs Canva: your output is already a first-class editable template.
- Chat-to-edit on the live template/board. Add a conversational sidebar that reads the current template's zone/widget JSON and resolves NL commands ('make the header bigger', 'use our brand blue', 'move the menu to the left', 'add a countdown to kickoff') into field mutations on the existing StyleableField/PropertiesPanel model. Mirror Adobe's two modes: inline-preview-then-apply for ambiguous asks, apply-then-confirm for unambiguous ones. Every change is a normal undoable edit on the canvas.
- Brand-from-URL as the universal on-ramp (you already scrape branding!). Extend the existing branding scrape into a Canva-Brand-Kit-Builder-grade extractor: palette + fonts + logo + (new) brand VOICE/tone, resolving into your var(--brand-primary)/var(--brand-accent) tokens, then auto-seed a first on-brand board. The Integration Concierge 'paste URL → propose stack + auto-seed template' vision IS this pattern — ship it.
- Always return 3 options, never 1 (Rise Vision/Canva). For a non-IT K-12/venue operator, one bad generation burns trust; three lets them pick and feel in control, and 'regenerate / try another variation' must be one tap away.
- Magic Reformat across signage shapes as a headline feature. Build AI-assisted reflow (not naive transform:scale) that re-typesets and repositions a board for 16:9 TV ↔ portrait poster ↔ long LED ribbon ↔ touch-kiosk. VenueOS's multi-shape reality (Taurus LED ribbons, portrait kiosks, 16:9 TVs, N-panel daisy-chains) makes this MORE valuable here than at Canva. Reuse the transform:scale wrapper as the floor and layer AI reflow on top.

For QSR/worship/K-12 operators with a paper menu, foamcore sign, or a competitor's TV, let them snap a photo → vision model → editable VenueOS template grounded in your widget registry. - Inline, proactive next-best-action chips (Adobe inline suggestions). This is where domain expertise beats generic Canva.
- AI-from-CMS-data auto-fill. Because VenueOS already owns the POS/menu/schedule/score feeds, AI should both WIRE the data binding and WRITE the copy (menu descriptions from POS items, 'tonight's game' from the schedule, lunch-special blurb). Generic tools can't do this — they don't have the operator's live data.
- Tier the AI economics exactly as planned and make the boundary explicit. Setup-time generation (Concierge: brand extract, first-board seed, 3-option generate) on the platform key; everyday creative (chat-to-edit, reformat, copy) on tenant BYOK — and when no key, say 'Configure your AI provider' rather than silently spending platform budget (this is already in CLAUDE.md; the research confirms it's the right model).

**Where we can leapfrog**
- Output that is editable BY CONSTRUCTION, not by luck. Canva had to BUILD A NEW MODEL to stop emitting flat images; VenueOS's schema-first architecture (zones/widgets/StyleableField/variants-register) means AI that emits your existing template JSON is editable on day one. Lean into constrained generation (Puck AI pattern) and you ship the thing Canva spent a year fixing — for free.
- Domain-grounded generation generic tools can't touch. Canva/Adobe don't know it's an 8-foot viewing distance, don't know about emergency fallbacks, Taurus Chromium-83 inset/gap constraints, ADA contrast on a brand palette, or sponsor-impression frequency caps. Bake these as proactive checks + generation constraints so VenueOS output is 'signage-correct', not just pretty.
- AI-from-YOUR-live-data. You own the POS/menu/score/schedule/weather feeds and the integration concierge. AI that both wires the binding AND writes the copy from live data ('tonight vs Lincoln HS, 7pm', POS-driven menu blurbs, auto-86) is impossible for design-only tools. This is the strongest moat.
- Multi-shape reformat is more valuable here than at Canva because signage shapes are wild — portrait kiosks, 16:9 TVs, long LED ribbons, N-panel daisy-chains, 320×1080 strips. A great AI Reformat across these is a flagship feature; Canva only cares about social aspect ratios.
- One platform, everyday signage + native life-safety + (sports) game presentation on the same screens. AI co-creation that spans 'build a lunch board' AND 'this board auto-flips to a lockdown alert' AND 'celebrate the goal' is a story no design tool or pure-signage CMS tells.
- Touch-kiosk app generation (OptiDev's frontier) grounded in a safe, sandboxed runtime you already operate. Describe-a-kiosk → editable multi-scene touch experience wired to your data, but inside VenueOS's null-origin sandboxed iframe + click-to-edit shim — secure-by-default app generation, not raw HTML the operator must trust.

**Pitfalls**
- UNEDITABLE / FLAT OUTPUT is the #1 trust-killer. AI that returns a baked image or markup that diverges from your component system forces refactor and can't be tweaked — Canva explicitly re-architected to a model with editable layers to escape this, and 'constrained UI vs AI slop' names it as why most generative interfaces fail (puckeditor.com/blog/ai-slop-vs-constrained-ui). Mitigation: generate into your validated zone/widget schema only.
- BRAND DRIFT across outputs. LLMs/image models 'can't hold a consistent brand voice over dozens of outputs without external scaffolding' and palette/type/tone drift as you generate more (venturebeat, venngage, okoone). Mitigation: inject the tenant Brand Kit (colors/fonts/logo/VOICE) into every call + a post-gen Brand Checker that flags/auto-corrects drift (Microsoft Copilot pattern).
- NON-DETERMINISM. Identical prompts yield different layouts run-to-run (puckeditor), which is jarring for operators expecting stability. Mitigation: constrain to schema, fix temperature, offer 'regenerate' explicitly rather than silent variance, and let edits be normal undoable mutations.
- LATENCY breaks the 'magic'. Operators expect 'seconds' (OptiSigns markets <30s, Rise Vision 'seconds'). A 30-90s spinner on chat-to-edit feels broken. Mitigation: stream/optimistic-apply, show inline previews fast, keep chat-to-edit edits small and local, and use a fast model (you already use Haiku for copy) for edit-resolution vs a bigger model only for full synthesis.
- COST blowout. Full-template synthesis and vision (photo→board) are expensive vs a copy sparkle. Your 3-tier model is correct, but enforce it: setup-time generation on platform key with hard caps, everyday creative on tenant BYOK, and NEVER silently spend platform budget on a BYOK action (CLAUDE.md already mandates 'Configure your AI provider' messaging). Watch vision-model cost on photograph-your-sign.
- ACCESSIBILITY / READABILITY blind spots. Generic models 'lack awareness of accessibility standards' (insights.wohlig) — they'll happily make 32px text or low-contrast brand-on-brand. For 8-ft signage this is a correctness bug. Mitigation: enforce min-font/auto-fit floors and WCAG-AA contrast as hard generation constraints + proactive warnings.
- Chromium-83 / WebKit output traps. If AI ever emits raw CSS/HTML (kiosk/app generation), it can emit inset/gap/backdrop-filter that dies on Taurus and minified JS that throws in Safari — both are documented multi-day fires in this codebase. Mitigation: generate into the schema (renderer handles compatibility) or run AI-emitted markup through the same taurus-safety + WebKit gates before it can ship.
- OVER-AUTOMATION / loss of control. 'Make it better' is great until it changes something the operator wanted. Mitigation: always show a diff/preview, keep a one-tap undo, and prefer inline-suggest-then-apply for ambiguous asks (Adobe's two-mode pattern) so the operator stays in the loop.
- Costume features. Industry pattern (and this codebase's own history) is shipping AI buttons that don't actually work end-to-end. Verify the full generate→edit→schedule→render loop on a real screen before claiming it (CLAUDE.md Verification-Before-Claim).
