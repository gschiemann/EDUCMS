# 面向 IT 团队的安全概览

VenueOS 是用于数字标牌和紧急警报的云服务。您的员工在网页管理后台中管理屏幕；每块屏幕运行 VenueOS 播放器，并从 VenueOS 云端接收内容和警报。本页面向负责评估它的 IT 和安全团队。

## 托管与数据位置

| 组成部分 | 作用 | 运行位置 |
|---|---|---|
| 管理后台 | 员工使用的网页应用 | Vercel，全球边缘网络 |
| VenueOS 服务 | 登录、内容、排程、警报和屏幕管理 | Railway，美国 |
| 数据库和文件存储 | 账户、设置和上传的内容 | 运行在 Amazon Web Services 上的 Supabase，美国 |
| 屏幕播放器 | 在每块显示屏上播放内容 | 显示屏或媒体播放器上的 Android 应用，或网页浏览器 |

所有客户数据都存储在**美国**。我们的各家托管服务商都会发布各自的独立安全审计报告。银行卡付款在 Stripe 托管的页面上完成，卡号绝不会到达 VenueOS。

所有处理客户数据的服务商及其处理时机，见[数据处理附录的附件 B](/dpa#subprocessors)。

## 登录与身份

- **密码**至少 8 个字符，只以加盐的 Argon2 哈希形式保存。登录尝试有频率限制。
- **两步验证**：通行密钥（Face ID、Touch ID、Windows Hello 或硬件安全密钥）、配有一次性备用码的验证器应用，以及作为备选的邮件一次性验证码。重置密码后 7 天内不接受邮件验证码。员工看到的具体步骤见[登录、通行密钥与两步验证](/help/signing-in)。
- **谁必须使用**：您的组织可以要求所有管理员和所有可发送紧急警报的人使用两步验证，管理员也可以要求任何个人使用。
- **首次登录**：每位新成员在首次登录时设置自己的密码和电子邮件地址。
- **单点登录**：支持任何 OpenID Connect（OIDC）身份提供商 —— 例如 Google Workspace、Microsoft Entra ID 或 Okta —— 并仅限您指定的邮箱域名。见[设置单点登录](/help/sso)。
- **会话**：访问凭证一小时内过期。“保持登录”使用存放在页面脚本无法读取的 Cookie 中的一次性轮换凭证；一旦旧凭证被重复使用，整个会话即被登出。

## 谁能做什么

| 角色 | 权限 |
|---|---|
| 管理员（组织） | 管理组织内所有地点、用户、品牌和内容 |
| 管理员（地点） | 管理一个地点的屏幕、播放列表、排程和员工 |
| 编辑者 | 上传和编辑内容及排程 |
| 查看者 | 只读访问 |

发送紧急警报的权限需**按人单独授予**。每个请求都限定在该人员所属的组织内，每次代码变更的自动化测试都会检查各组织的数据保持隔离。

## 数据保护

- **传输中**：所有连接都使用 HTTPS（TLS），管理后台启用 HSTS。
- **静态存储**：数据库和文件存储由托管服务商加密。VenueOS 还会额外加密两步验证密钥、单点登录密钥以及您所连接服务的凭证。
- **上传的文件**按实际内容而非文件名检查。伪装、损坏或不支持的文件会被拒绝。
- **私有文件** —— 播放器软件、平面图和问题报告截图 —— 只通过短时有效的签名链接提供。
- VenueOS **不需要**学生档案。在学校管理员确认其目录信息和照片授权政策之前，学生姓名和照片在公共体育屏幕上保持隐藏。

## 审计日志

特权操作都会被记录：登录和两步验证事件、用户和权限变更、内容和排程变更、紧急警报和解除警报，以及屏幕的配对和移除。每条记录都包含操作人、组织、网络地址、操作、对象和时间。数据库规则禁止编辑或删除审计记录，管理员可以在后台筛选审计日志并导出为 CSV。

## 屏幕

- **配对**：屏幕显示一次性代码，由管理员在后台输入。屏幕随后获得自己的凭证。
- **设备凭证**每块屏幕独有、短时有效并自动续期。在后台移除屏幕后，它的下一个请求即被拒绝。
- **最小权限**：屏幕只能获取分配给自己的内容，只能报告自己的状态。
- **播放器软件**：发布版本经过签名，每次更新在安装前都会与 VenueOS 记录的指纹比对。
- **已保存的内容**在存入屏幕前会按指纹校验。紧急内容保存在单独的受保护存储中。

网络需要放行的内容见[网络与防火墙要求](/help/network-requirements)。

## 紧急警报

只有获得警报权限的人才能发送警报，需刻意长按或输入确认词，每次警报和解除警报都会记入审计日志。警报消息在发出前经过加密签名，通过实时连接送达屏幕；该连接不可用时，改由常规轮询送达。详情（包括系统不覆盖的情况）见[紧急系统概览](/help/emergency-system)；显示在常规内容之上的文字和多媒体消息见[紧急广播与员工 SOS](/help/emergency-broadcast)。

## 我们如何开发和运行

- 每次变更都经过版本控制和自动检查：类型检查、包括紧急警报链路在内的自动化测试、组织隔离检查、密钥泄露扫描和依赖漏洞审计。
- 密钥保存在托管服务商的密钥库中，绝不写入源代码。
- 管理后台发送内容安全策略（CSP），并防护跨站请求伪造和点击劫持。服务器对用户提供地址发起的请求无法访问内部网络。
- 新版本只有在通过健康检查后才接收流量。数据库每晚加密备份，保留 30 天。实时健康状况见[状态页面](/status)。
